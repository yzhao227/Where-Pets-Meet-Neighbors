## 视频修复与证据

- 视频进入所属资源分包后，复制到本页独立的微信用户文件，读取并核验 MP4 文件头与大小。通过 `wx.compressVideo` 获取平台临时视频路径，再挂载原生播放器。
- 仅当 API 明确不支持，或开发者工具明确报告缺少 ffmpeg 依赖时，回退到已验证的用户文件；手机编码失败仍显示可重试错误，不吞掉实际故障。
- 播放等到页面 `onReady` 和视频源 `setData` 提交均完成后才启动；真实时间进度到达后才解除缓冲状态。准备超过 20 秒、启动或停滞超过 8 秒会出现恢复入口，避免无限转圈。
- 重试重建视频节点，过滤旧请求回调，离页暂停并仅清理本页生成的文件。预览运行时同步补齐一次性 `onReady` 调用。
- 首帧前切到后台再返回时恢复首次播放请求；已有首帧且用户暂停的视频保持暂停。节点提交或 `onReady` 缺失时也有 8 秒截止与重试入口。
- 13 个打包 MP4 已完整解码核验，没有发现共同的编码损坏；原视频文件未重新编码或替换。
