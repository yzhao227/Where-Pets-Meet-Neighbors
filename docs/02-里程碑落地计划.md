# 有宠有邻：里程碑落地计划

版本：规划稿 v0.4 · 更新：2026 年 9 月 29 日

配套文件：[产品设计蓝图](01-产品设计蓝图.md)

本计划从“让爱宠人士建立持续联系”出发，逐步加入付费活动、本地服务和商品交易。覆盖所有爱宠人士，宠物档案选填；未养宠用户始终可以参与内容、圈子和适合的活动。

当前代码为「有宠有邻」v0.4 部署基础版，在社区、活动、核验与宠物资料功能之上，补充草稿恢复、异步图片审核、服务运行状态、数据库初始化、维护与发布工具。真实微信账号、云环境、平台能力和真机验证仍待接入。代码与本机体验的完成情况见项目 README；微信接入、真实多人验收和下述经营指标需要分别完成，不因增加内容功能自动视为通过某个里程碑。

## 使用前提与推进规则

- 团队假设：创始人负责产品与社区运营，1–2 名开发，设计和测试兼职；城市、预算、合作资源待定，可据实际情况调整。
- 每阶段都先做小范围试运营。对应业务通过验收后才扩大；上线日期不等于经营验证通过，新增板块也不自动获得扩张资格。
- 七阶段是建议投入顺序，不是所有商业分支的硬串行依赖。共用基础与信任能力必须过关，具体分支有真实需求且履约就绪时，可在资源允许的情况下调整先后。付费活动未成立，不阻断已验证的洗护需求；商品、喂养、遛狗各自评估。
- 下表是范围级开发估算，供排期讨论，非工期承诺。不含主体与支付申请、审批、招商等待、招聘、外部接口延误；正式排期须在需求和人员确定后重估。运营观察可以与开发交错进行。
- 所有数字均为首轮内部建议，不是行业标准。样本太少时记录事实与访谈，不宣称已经验证规模化；涉及复购时至少覆盖该业务实际消费周期。
- 验收分三层：发布前检查功能与运营责任；小样本验证是否值得继续投入；完整消费周期和区域经营结果决定能否扩大。前两层通过不等于可以规模化复制。

| 阶段 | 开发范围级估算 | 运营观察窗建议 | 核心放行问题 |
|---|---|---|---|
| M0 人工需求验证 | 0–1 周，表单和原型 | 2–4 周 | 是否有人愿意再次联系？ |
| M1 小程序社区首版 | 4–8 周 | 首批稳定用户进入后至少 4 周 | 社区能否持续产生用户间互动？ |
| M2 关系增强／付费活动两个分支 | 合计 2–4 周，收费基础另行估算 | 关系观察至少 4 周；付费活动至少 4 场并观察再次参与 | 关系是否持续？付费体验是否独立成立？ |
| M3 到店洗护交易 | 4–8 周 | 试单后覆盖至少一个正常复购周期 | 服务能否可靠成交并留下收益？ |
| M4 精选商品与商家工作台 | 4–8 周 | 至少覆盖一次补货、提货与售后周期 | 加购是否增加贡献而非负担？ |
| M5 上门喂养与遛狗 | 合计约 6–10 周，分批交付 | 两类服务各自完整观察 | 每一类服务是否有可靠履约能力？ |
| M6 复制与利润提升 | 按 2–4 周小迭代推进 | 原片区至少连续 3 个经营月，兼顾季节性 | 方法能否复制、利润是否改善？ |

**首次收费前的共用基础：**明确交易和退款责任、合适的支付与结算路径、订单状态、退款及对账、客服和投诉处理；覆盖重复支付通知、失败重试及账单差异。由第一个启动的收费分支建设并共享，建议另预留约 2–4 周开发范围，接入条件确定后重估。以上交易阶段估算以复用这套基础为前提；从首笔收费开始核算利润。

## M0：人工需求验证

**交付物：**确定一个片区和一种主要社交场景；建立 2–3 个小圈子；准备兴趣登记、访谈提纲、活动说明和反馈表；至少设计一种无需带宠参加的活动。梳理用户从哪里来、为何参与、希望再次见谁。

**用户流程：**看到邀请 → 登记兴趣与大致片区 → 加入适合的小圈子 → 参加话题或小聚 → 收到再次参与的邀请。

**验收：**建议招募 30–50 位自愿参与者，观察 2–4 周。每次记录邀请人数、实际参与人数、获得回应人数和重复参与人数；访谈养宠及未养宠参与者。必须发现真实的重复联系、清楚的参与理由和可持续组织的场景，不能只凭“觉得产品不错”。

**责任与账目：**创始人主责，设计支持原型，开发协助轻量记录；计入招募、场地及组织工时，暂不要求收入。

**未通过：**缩小场景、调整活动时间和参与门槛，重新验证。若用户只想获取知识，就先检验内容需求，暂缓完整交友功能。

## M1：小程序社区首版

**交付物：**可在一个片区试运营的小程序、基础管理后台、内容与活动规则、运营值班及问题处理表。目标是跑通“找到圈子—得到回应—再次回来”。

### 页面与 P0 范围

| 页面 | 首版必须具备的能力 |
|---|---|
| 初次进入／个人资料 | 浏览后按需注册；后台核验、前台昵称；资料选填；主页公开和头像旁宠物展示独立控制；核验前主动同意协议与隐私说明 |
| 社区（首页） | 推荐少量圈子、近期活动和圈内内容；新用户能直接找到一次参与机会 |
| 附近 | 按手选片区展示真实圈子和活动；首版没有空白商城或不可预约的服务入口 |
| 圈子列表／详情 | 主题、参与条件、规则、加入与退出、圈内内容；初期由运营创建圈子 |
| 发布／内容详情 | 图文发布、评论与回复、删除自己的内容；举报入口和处理状态 |
| 活动列表／详情 | 时间、公共地点、人数、组织者、取消规则和活动讨论；标明无需带宠／可带宠／需要带犬等具体条件 |
| 报名／我的活动 | 报名、人数校验、取消、活动变更通知、活动后反馈；本阶段以免费活动为主 |
| 消息 | 回复、报名结果、活动调整、举报处理等站内消息；外部提醒按用户授权提供 |
| 我 | 资料、宠物档案、加入的圈子、参与记录、隐私设置、退出登录和账号注销入口 |
| 管理后台 | 用户与圈子管理、内容审核、举报处理、活动及报名管理、必要操作记录与限权的汇总数据导出 |

其他 P0：举报和拉黑、身份权限、必要的个人信息授权、备份与恢复、错误监测、关键行为统计。普通用户不能查看活动成员联系方式或精确住址；公开位置使用片区或公共场所。建立内容处理与申诉流程，所有身份均适用同一套行为规则。

### 主流程与异常流程

**主流程：**选兴趣和片区 → 加入圈子 → 回复或发布一条内容 → 获得回应 → 报名适合的活动 → 活动后继续交流。没有宠物、没有定位授权也能完成这条路径。

- 空圈子、无人回应：提供运营引导和真实活动信息；记录是否由运营兜底，不制造虚假互动。
- 发布失败或网络中断：保留可恢复草稿，明确发送状态，避免重复内容。
- 名额已满或重复点击：给出明确结果，重复报名只保留一份有效记录。
- 活动变更、组织者取消或用户退出：更新报名状态，通知受影响用户；允许查看最新安排。
- 被拉黑、违规内容、账号注销：隐藏不应继续展示的信息，限制相应互动，处理后台保留的必要记录与删除要求。
- 不愿公开位置：允许手选片区；所有通知失败均可在小程序内查看结果。

**验收：**设计与测试完成养宠／未养宠、授权／不授权、新人／老用户的完整路径检查，严重功能和隐私问题归零；运营能独立处理发布、报名和举报。建议观察首批 30–50 位完成首次有效参与的用户连续 4 周，逐周报告重复互动、圈子回访和自发邀请；同时呈现人数与分母。若全部交流仍依赖运营，不能认定社区已成立。

**职能与收益：**创始人负责内容和组织，开发负责功能与数据，兼职设计测试负责可用性验收。记录每周运营工时、每位有效参与者的获取成本，暂不以收入作为本阶段门槛。

**明确后置：**陌生人匹配算法、开放私聊、直播短视频、全城地图、商家自由入驻、商城、在线服务预约、会员充值、多城市运营。M1 未通过时优先调整场景、圈子规模与回应机制，再决定是否补功能。

## M2：关系增强与付费活动两个独立分支

**M2A 关系增强：**交付双方同意后的私聊、再次邀约、活动小组；用户从共同互动进入双方同意的联系，再自主邀约。由运营负责关系质量，开发实现权限和通知，测试确认拒绝、撤回、拉黑及举报。观察至少 4 周的重复互动和自发邀约；若新增功能没有改善联系，回到圈子和活动体验。该分支不以收费为前提。

**M2B 付费活动：**在共用收费基础上交付付费活动报名、取消退款、核销及账单。先审核组织者，再逐步开放发起活动。基础社区互动保持易于使用。以下付费流程和经营验收仅适用于 M2B。

**用户流程：**了解主题、组织者和完整价格 → 报名付款 → 收到确认 → 到场参加 → 核销与反馈 → 自愿再次联系或购买。

**验收：**下单、重复支付通知、活动未成团、取消退款、通知失败均能正确处理；建议观察至少 4 场完成活动，分别记录可售名额、实际付费人数、到场人数、退款人数、再次付费人数。出现按公开价格再次购买的用户，活动扣除变动成本后有正贡献，才扩大频次。

**职能与账目：**运营负责组织和客服，开发负责交易，兼职财务或创始人核账。收入为平台实际取得的组织服务费或自营活动收入；成本包括场地、组织者、物料、支付、优惠和售后，不能把代付给场地的钱全部视作平台利润。

**未通过：**调整主题、体验、价格和成本；若参与者只接受免费活动，保留社区验证，暂停依赖活动收入扩张。

## M3：到店洗护交易

**交付物：**3–5 家可真实接单的试点门店；套餐、预约、订单、核销、退款及结算功能；提供最小商家接单、核销和账单入口。商家需提交真实价格、可接时段、联系人和服务规则；口头合作意向不计作有效供给。

**用户流程：**选套餐并提交必要宠物信息 → 门店确认时间与最终价格 → 用户限时付款 → 到店服务 → 完成核销 → 评价、售后或复约。附加服务及加价须用户确认。

**验收：**先明确交易责任方、收款和结算路径、退款及开票责任；验证拒单、付款超时、改期、爽约、追加项目和退款争议。建议用前 30–50 笔已付款订单观察完整流转，分母包含取消和退款单，不能只看成功单；再覆盖至少一个实际复购周期。核账一致、履约问题可控、商家愿意继续合作、每单贡献为正后扩大。

**职能与账目：**创始人招商，运营协调履约，开发维护交易，财务职能核账。按完成且扣除退款后的约定实收金额抽佣；单列优惠、支付、客服及退款损失。

**未通过：**下架不可靠套餐、减少合作店、修正定价或接单规则；复购不足时调查原因，不用持续补贴掩盖问题。

## M4：精选商品与商家工作台

**交付物：**少量精选商品、库存确认、独立商品订单、提货凭证和退换货；在已有商家入口上补齐库存及更完整的工作台，统一管理服务档期、库存、订单和账单。先人工审核入驻，商品自提稳定后再增加配送。

**用户流程：**查看商品与商家 → 确认库存、价格和取货条件 → 支付 → 到店提货 → 核销或售后。与洗护同店加购，但商品和服务分别记录履约及退款。

**验收：**库存不足、重复提货、缺货退款、退换货均可处理；有补货及售后记录，库存和账目一致。试运营按“看到推荐的人数—下单人数—完成提货人数—退款人数”记录转化，核算新增订单贡献。配送单独验证运费、时效、破损与责任后开放。

**职能与账目：**招商和运营负责选品及商家质量，开发负责工作台，财务核对佣金。商品佣金按利润协商；计入售后和平台承担的配送成本。暂不依赖入驻年费。

**未通过：**减少商品品类、降低库存更新负担；若加购收益被售后吃掉，暂停该品类，不因用户规模增长而全面铺货。

## M5：上门喂养与遛狗，分别放行

**交付物：**经审核的服务团队、人员安排、服务须知、订单、服务记录、异常与赔付处理机制。先逐单试运营，不开放无限量接单。

| 类别 | 用户流程与独立验收条件 |
|---|---|
| 上门喂养 | 填写宠物与喂养要求 → 确认服务人员、时间及入户方式 → 支付 → 到达和完成记录 → 售后；必须有人员身份与授权、钥匙或门禁信息管理、无法入户、宠物异常及紧急联系流程 |
| 遛狗 | 填写体型、性格、健康和牵引要求 → 确认人员与路线边界 → 支付 → 交接、服务及归还记录 → 售后；必须有接单条件、牵引规范、极端天气取消及走失、冲突、伤害的处置流程 |

**验收：**两类业务各自按已付款订单全量检查履约及异常，不相互代替。每单有责任人和完整记录，服务容量明确，责任约定及相应保障落实；发现严重缺陷先暂停相关服务。

**职能与账目：**需要明确的履约负责人及可联系的客服，创始人不能仅靠开发系统解决人员质量。按类核算佣金、人员协调、客服、保障和损失成本；收益为正且容量稳定后增加供给。

**未通过：**缩小服务半径或接单条件，更换服务团队；暂不开放不具备处理能力的宠物和场景。

## M6：复制与利润提升

**交付物：**片区经营账、商家与组织者手册、服务质量检查、可复制的招募方法。复制已经成立的业务组合，不要求前述所有板块成功。先复制相邻片区，再讨论其他城市。会员、商家工具订阅和商业推广分别试验，付费展示明确标识；利润从首次收费就跟踪，本阶段着重扩大有效业务。

**流程：**老用户复约或相关加购 → 稳定履约 → 推荐新成员 → 新成员进入圈子与消费；评估每一步成本和收益。

**验收：**原片区建议连续 3 个经营月保持正贡献，且覆盖相关复购周期；固定成本能否覆盖单独报告。新片区有负责人、服务供给和独立预算，按同口径观察，不以总交易额掩盖单片区亏损。

**职能与账目：**创始人分配预算，运营负责片区质量，财务分析利润，开发优先降低重复劳动。依次改善复购、售后损失、相关加购、获客效率，再优化收费与扩张。

**未通过：**暂停继续开区，修复已有区域；只保留能贡献收益或明确支持核心关系的板块。

## 前 14 天执行安排

| 时间 | 创始人／运营 | 设计、开发及验收产物 |
|---|---|---|
| 第 1–2 天 | 选片区和主场景，列招募渠道；覆盖养宠与未养宠人群 | 明确用户路径、问题假设、信息收集边界 |
| 第 3–4 天 | 做首轮访谈，记录真实经历与已有替代方式 | 低保真原型；统一参与、回应与重复联系的记录表 |
| 第 5–7 天 | 建立小圈子，发布首次话题，确认公共活动场地 | 测试报名、取消、位置隐藏及无宠参与路径；记录修改 |
| 第 8–10 天 | 在参与者时间允许时组织首次活动，访谈未参加者 | 整理回应与参与数据；形成 M1 页面和 P0 清单 |
| 第 11–12 天 | 邀请再次参与，检查是否出现用户自发联系 | 验证关键页面，估算开发与长期运营成本 |
| 第 13–14 天 | 复盘场景、运营负担和招募效果，选择继续或调整 | 冻结一版 M1 范围、验收清单及数据口径，再确定排期 |

两周不足以证明长期留存；未发生的活动和重复参与继续观察，不能为了日期补写验证结论。

## 统一指标与经营口径

**双向重复互动人数：**统计周内，在两个不同自然日与同一人分别发生双向交流的去重用户数；一次双向交流要求双方均发送评论、回复或消息，单纯点赞、系统通知、运营账号及测试账号不计。同一人有多个伙伴仍只计一次。公开讨论可以排除明显广告或纯表情；私聊只按事先告知的发送与回复行为统计，不读取私聊内容来评分。该指标是关系行为的近似信号，交流是否有价值通过自愿回访判断。

**双向重复互动占比：**上述人数 ÷ 当周至少发布、评论、回复、私聊或实际参加一次活动的真实去重用户数，分母同样排除运营及测试账号。分子、分母、统计周同时展示。另按新用户首次参与周建立队列，记录其次周是否再次参与；报名未到场不算实际参加。

**平台收入：**平台实际取得的佣金、组织服务费、订阅等；交易总额单独列示。自营活动按收入和成本完整记录，代收款不直接等同收入。

**订单贡献：**该订单的平台收入 − 平台承担的优惠、支付费用、退款净损失及直接履约和客服等变动成本。退款对应佣金先冲回收入；退款净损失只计算未被其他项目计入的不可追回成本或赔付，避免重复扣算。共用人工按一致规则分摊，暂无法精确计量时同时披露工时。

**区域经营贡献：**区域内全部订单贡献及其他业务贡献 − 该区域获客费用 − 该区域未计入订单的固定运营费用。**整体经营结果：**所有区域经营贡献之和，再扣除尚未分摊的产品开发、管理和工具等公共固定成本。每项成本只归集一次，按业务、片区和月份分别核算。

**获客回收：**同期渠道投入 ÷ 新增有效参与者，以及 ÷ 新增首购用户，分别展示；用同一批首购用户后续累计贡献观察回收，不能把全站收入与某渠道成本直接相减。扩张前同时检查关系质量、履约质量和经营结果。
