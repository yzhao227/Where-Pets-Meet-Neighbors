# 有宠有邻 v0.4：开发接口约定

所有页面通过 `miniprogram/services/api.js` 的 `call(action, payload)` 调用，返回 Promise，成功直接返回 data，失败抛出含 message/code 的 Error。云函数封装为 `{ ok: true, data }` 或 `{ ok: false, error: { code, message } }`，由该适配器解包。客户端不提交操作者身份；云端从微信上下文确定用户。`getUserProfile`、`followUser`、`blockUser` 中的 `userId` 仅为目标用户。时间统一为毫秒时间戳。列表通常返回 `{ items, nextCursor? }`，详情附带列表时以表中字段为准。

默认是明确标识的本机演示模式；真实模式调用 `community` 云函数。真实环境不自动灌入虚构用户或虚构活动。

## 公共结构

- User（本人）: `{ id, nickname, avatar, area, bio, pet: { name, type: 'cat'|'dog'|'other' } | null, publicProfile, showPet, verification: { status: 'unverified'|'demo_verified'|'phone_verified', maskedPhone? }, isAdmin }`。公共作者返回 `{ id, nickname, avatar, pet? }`，仅在 `showPet === true` 且有宠物资料时返回宠物名字和类型。核验状态与手机号掩码只出现在本人资料。`area` 可为空字符串，非空时须属于已开放片区，永不在公共主页返回。旧资料缺少的 `publicProfile`、`showPet` 默认为 `false`，不扩大原有公开范围。
- Author（主页）: `{ id, nickname, avatar, publicProfile, showPet, bio, pet, isMine, isFollowing, postCount, followerCount, followingCount }`。介绍只在本人或 `publicProfile` 开启时返回，否则 `bio: ''`；宠物在本人、`publicProfile` 或 `showPet` 任意条件满足时可返回，否则 `pet: null`。已公开的帖子仍可在主页查看。不返回 OpenID、手机号、核验状态、片区或管理权限。
- Circle: `{ id, name, description, memberCount, isJoined, accent, icon }`。
- Post: `{ id, author, circle: { id, name }, title, text, images: string[], kind, topics: string[], coverIndex, cover, eventId, event, createdAt, commentCount, likeCount, isLiked, isBookmarked, isMine }`。`kind` 为 `daily`、`question` 或 `meetup`。无图时 `cover: ''`、`coverIndex: 0`。可见关联活动 `event` 至少含 `{ id, title, startAt, location, status, petPolicy }`，无关联、活动删除或被屏蔽时为 `null`。
- Comment: `{ id, author, text, createdAt, replyToName?, isMine }`。
- Event: `{ id, title, description, location, startAt, endAt, capacity, attendeeCount, petPolicy: 'none'|'optional'|'dog', circleId, hostName, cover, status: 'active'|'cancelled', isJoined, isMine, cancelReason? }`。已结束由 endAt 判定。
- Message: `{ id, title, text, createdAt, isRead, targetType: 'post'|'event'|'system', targetId }`。
- Report（仅管理员）: `{ id, targetType, targetId, reason, description, status: 'open'|'resolved'|'dismissed', createdAt, reporter: { id, nickname, avatar }, targetSummary, targetTypeForLink: 'post'|'event'|'user', targetIdForLink }`。评论举报链接到原帖子或活动；目标删除后保留举报记录并显示“内容已删除”。

## 首版共同约束

- 图文最多 3 张图片，正文 1–1000 字（有图片时正文可为空），评论 1–300 字；圈子成员才能在该圈发帖。
- 标题选填、最多 40 字；话题最多 3 个且不重复，选自 `宠物治愈时刻 / 新手养宠 / 一起散步 / 没养宠也能来 / 宠物友好去处 / 养宠经验`。封面必须来自本帖图片。关联活动必须存在且本人可见；不要求活动尚未开始，以便关联活动回顾。
- 搜索词最多 60 字，字面匹配标题、正文或话题，不解释为正则表达式。`following` 展示已关注作者，`circles` 展示已加入圈子，空筛选不限制结果。云端采用有界扫描与继续游标，扩大内容量后应独立评估搜索索引。
- 点赞、收藏和关注生成去重的真实站内通知，不给自己发送；重复开关不刷新旧通知时间或重置已读。评论、报名、活动变更和治理通知继续保留。屏蔽移除双方关注及彼此内容上的点赞和收藏；取消屏蔽不会自动恢复这些关系。删除内容/注销账号清理相应关系。
- 图片统一通过 `api.uploadImages(count=3)` 选择并保存本机副本，再申请票据和上传。它返回整个未消费队列的快照对象，取消选择保留已有结果；不是图片数组。最多 3 张，已完成、待审和失败记录合计占用名额，单张最多 5 MB，详见下一节。
- 有游标的页面提供“查看更多”，按服务端返回值继续加载，合并时按记录 ID 去重。刷新或切换筛选后丢弃此前尚未完成的分页请求。云端默认每页 20 条；本机演示的部分小列表一次性返回全部条目，没有 `nextCursor` 时视为已加载完成。
- 活动免费；只有管理员可创建/修改/取消。标题 1–60 字、介绍 1–1000 字、地点 1–120 字、人数 2–100 人，需关联已有圈子。新建活动开始时间须在未来，结束晚于开始。新报名须在开始前、活动未取消且有名额；重复报名幂等，取消已有报名释放名额。服务端支持开始后或取消后退出已有报名；当前页面仅在开始前且活动未取消时提供取消报名入口。
- 已取消或已开始的活动不能修改；已结束的活动不能取消。取消原因 1–80 字。修改已有人报名的活动须保留已报名人数；实际变更和取消会通知报名者。并发报名由云端事务保护。
- 初始化城市最多 30 字、片区 1–20 个且每个最多 40 字。云端运营联系方式 1–160 字；当前管理页限制 100 字，落在云端和本机演示共同可接受范围内。
- 用户只能删除自己的内容；管理员可治理违规内容。被屏蔽作者从帖子、评论列表和详情中隐藏。用户的私有消息只对本人可见。
- `config.js` 仅保存公开配置：`mode: 'demo'|'cloud'`、`cloudEnv`、`appName`。任何管理员凭据不得写入客户端。
- 原生页面遵循此约定：`pages/community/index`、`pages/nearby/index`、`pages/messages/index`、`pages/me/index`、`pages/circle/index`、`pages/post/index`、`pages/event/index`、`pages/compose/index`、`pages/profile/index`、`pages/records/index`、`pages/blocked/index`、`pages/manage/index`、`pages/moderation/index`、`pages/author/index`、`pages/register/index`、`pages/policy/index`、`pages/petstats/index`、`pages/health/index`。作者页参数 `userId`；记录页 `type` 支持 `posts/circles/events/bookmarks/following`。
- 为浏览器中的同源原生页面预览，使用基础 WXML（view/text/image/button/input/textarea/picker/switch/scroll-view/block）、wx:if/elif/else、wx:for、bindtap/catchtap/bindinput/bindchange/bindconfirm 与 data-*。避免 WXS、自定义组件和模板内函数调用。页面脚本可使用 wx.showToast/showModal/showActionSheet、navigateTo/switchTab/navigateBack、setNavigationBarTitle、chooseMedia/chooseImage、previewImage、stopPullDownRefresh、setClipboardData；使用 Page、getApp。

## 上传状态、草稿与本机清理

云端 `UploadStatus` 为以下三类之一；本机演示的完成仅表示本机文件已登记，不表示真实审核通过：

- `{ status: 'complete', ticketId, fileId }`：已审核发布的最终文件标识。
- `{ status: 'pending', ticketId }`：尚未完成，不返回可发帖的文件标识。
- `{ status: 'rejected'|'expired', ticketId, message }`：需移除并重新选图；内部 `cleanup` 状态对客户端显示为 `expired`。

`api.uploadImages(count)`、`api.resumeUploads()` 和 `api.discardUploads(ticketIds)` 均返回以下队列快照：

```js
{
  images: ['已完成的文件标识'],
  completed: [{ ticketId, fileId }],
  pending: [{ ticketId, status: 'pending', message }],
  failures: [{ ticketId, status, code, message, retryable }]
}
```

`images` 只包含完成项；`failures` 的 `status` 可为 `retry`、`rejected`、`expired`、`source_missing`。尚未取得服务端票据时，结果中的 `ticketId` 是本机队列编号，仍可传给 `discardUploads`。读取与恢复按账号及演示／云环境隔离，一项失败不丢失其他已完成图片。默认每次最多附加两次间隔 750 毫秒的状态查询，之后返回待审；重新进入编辑页或主动重试可继续查询，不依赖长时间阻塞等待。

队列保存在 `youchong.uploadQueue.v1`。正文、标题、圈子、话题、封面、关联活动和图片票据由编辑页另存于 `youchong.privateDrafts.v1`。它们是当前设备的草稿，没有云端草稿同步；保存失败会明确提示，不能承诺存储空间不足时仍已保存。`resumeUploads` 不重新选择相册图片；已保存的源文件及票据用于恢复。待审或失败项必须完成或移除，页面才允许发帖。`createPost` 仍由云端核验上传归属与完成状态，客户端队列不能替代审核。

发帖成功后消费所使用图片的队列记录；本机演示保留帖子正在使用的本机图片，云端模式清理本机源副本。云端模式先保存 `consumed` 标记，再删除本机副本；文件删除失败时保留清理记录，不重新展示为可发布图片。若本机存储本身无法写入，则该标记也可能未保存，页面必须保留“发布成功、本机清理失败”的区分，不承诺草稿已经清除。主动移除图片如果删除本机文件失败，会保留对应记录并报 `LOCAL_CLEANUP_FAILED`，可继续重试。

若 `createPost` 或 `deleteAccount` 已成功，而后续本机草稿／图片清理失败，`api.call` 仍返回成功结果，并可附加：

```js
{ localCleanup: { status: 'failed', message: '已完成业务操作，但本机清理未完成' } }
```

界面应显示“已发布／资料已清除，本机还需清理”，不可把它当作业务失败自动重发。`api.clearLocalUploads()` 只清理当前设备的图片队列及副本，返回 `{ success: true }` 或本机清理错误；它不调用注销或发帖，也不删除云端帖子。个人页的重试操作同时清理文字草稿。服务端已完成的操作如果响应在网络中丢失，当前版本没有通用请求幂等键；不能将这种不确定结果与明确的 `localCleanup` 成功结果混为一谈。

云端异步流程为：本人源文件 → 服务端隔离副本 → 微信加密回执 → 摘要校验 → 已审核发布副本。隔离路径在写入前登记到上传票据；最终发布路径也在服务端事务中预先登记，便于失败后维护回收。回执只记录结果，不直接发帖；签名、加密接收方、AppID、事件版本和审核编号验证通过后才持久化，保存失败返回 HTTP 503 以允许重试。回调入口不是普通客户端 action，不接受客户端伪造的审核结论。副本必须经真实存储规则限制客户端读写，随机路径或摘要本身不构成访问控制。

## v0.4 核验、政策与统计约束

- 演示协议版本和云端默认版本均为 `2026-09-29`，云端可配置当前协议与隐私版本。同意状态必须是布尔 `true`，提交版本必须与服务端一致。政策页面从 `getPolicies` 读取实际内容；注册页在版本或正式政策配置变化时清除尚未提交的勾选状态。
- 云端 `OPERATOR_CONFIG` 提供 `name`、`contact`、`retention`、`termsVersion`、`privacyVersion`、`policyApproved`，以及可选的各 action `rateLimits`。主体、联系方式与保存期限必须满足有效值检查，且 `policyApproved === true` 才得到 `policyConfigured: true`。占位值或未确认配置仍返回草稿，真实核验报 `POLICY_NOT_CONFIGURED`。这只是配置门槛，不代表法律审查、微信审核或完整的政策管理系统；现有条款由服务端模板生成，改变实际业务或条款还需修改并审查文本。
- 浏览与个人资料编辑可先使用；新增帖子、评论、活动及活动修改，新增圈子成员／活动报名／关注／点赞／收藏，以及上传票据、完成上传和云端查询审核状态需要核验。取消社交关系、退出与取消报名、管理员取消活动、举报、屏蔽、内容删除、账号清理等补救操作不受此门槛阻止，仍遵守原有归属或管理权限。
- 后端执行上述门禁；客户端显示、缓存或传入 `verified` 字段不能绕过。未核验返回 `VERIFICATION_REQUIRED`，界面引导加入页，成功后返回原页面，不自动发布或报名。上传前也先检查状态，避免先选择图片再被核验流程打断。
- 云端身份只由受信微信上下文确定。手机号原始值仅在服务端授权码交换时短暂处理；持久化带密钥的摘要、掩码、核验时间和同意记录，不在公开用户／作者／评论／举报响应中返回。真实核验适配器未启用时 `phoneEnabled: false`，不回退为模拟核验。
- 首次绑定后重复核验返回已有结果，不支持换绑。修改政策版本目前不会自动撤销已有核验或触发全体账号重新同意；需要这类政策升级流程时应另行实现。
- `getPetStats.totalUsers` 是当前有效账号数；每个账号最多登记一份宠物资料。`publicPetProfiles` 只计有宠物且 `showPet === true` 的账号。仅主页公开不计入头像旁展示数量。`profilesWithoutPet` 表示未填写，不能等同于未养宠。
- 演示环境保留旧存储键和已创建内容，未核验旧账号不能通过持有历史帖子绕过核验。演示核验和云端核验状态互不通用。
- 微信原生核验按钮使用 `open-type="getPhoneNumber"` 和 `bindgetphonenumber`。浏览器只显示普通点击的模拟按钮，不能产生真正的微信手机号授权凭据。

## 账号生命周期与运行边界

云端账号内部使用 `active → deleting → deleted` 状态和每次创建生成的 `lifecycleId`。这些字段不属于客户端可写资料，也不作为公开身份返回。关键写入在事务中重新检查当前生命周期；注销前已开始、后来才返回的核验、发帖、互动或上传请求不能写回重新建立的账号。

注销先锁定为 `deleting`，再清理资料、身份绑定、内容、社交关系、上传和相关运行记录。清理失败时仍保持 `deleting`，需要重试 `deleteAccount`；其余业务返回 `ACCOUNT_UNAVAILABLE`。并发清理使用租约避免重复执行。完成后留下最小状态记录 `{ status: 'deleted', lifecycleId, deletedAt }`，不能描述为数据库中从未存在过该账号。再次访问须经 `bootstrap` 建立新的生命周期，并重新核验；取消活动等必要历史状态及其他治理记录按具体功能保留，未实现自动法定留存或备份到期删除体系。

如果存在 `status: 'processing'` 且 `leaseUntil` 尚未到期的图片处理任务，`deleteAccount` 返回 `ACCOUNT_UNAVAILABLE`，保留 `deleting` 账号和上传票据，提示稍后重试。这样正在进行的存储写入结束后，其预登记路径仍可用于清理；本次响应不能显示为“账号已清除”。

部署默认使用演示模式，真实手机号核验和图片上传关闭。云端入口在私有集合缺失或数据库访问规则尚未确认时返回 `SETUP_REQUIRED`。真实手机号能力需显式启用、配置服务端摘要密钥及实际可用的微信接口；真实注册还必须满足正式政策条件。图片需显式开启并选择已验证可用的同步／异步审核方式；异步审核另需加密回调配置和隔离区权限确认。文字内容安全接口失败时拒绝相关写入，不回退为本机演示或跳过审核。

`getHealth` 的能力标志反映当前配置与适配器可用条件，**不证明微信接口实测通过、定时任务正在运行或平台已经审核通过**。`maintenanceEnabled` 表示维护密钥配置条件满足；最近执行结果需看时间字段。维护由受控服务端入口分批重试通知、回收未被帖子引用的过期文件和频次记录，客户端不能通过伪造触发器字段调用。频次限制由云端事务计数，命中返回 `RATE_LIMITED`；退出、取消等补救操作不套用新增关系的限额。

当前离线测试验证业务状态、持久化适配器、加密协议和重试逻辑，未替代真实微信环境中的手机号授权、内容安全接口、回调 HTTP 封装、CloudBase 权限／索引／事务与手机交互验收。部署步骤与实测清单见 [部署基础](../infra/README.md) 和 [云开发接入说明](../cloudfunctions/community/README.md)。

## 附近宠友接口（2026-09-30）

`listNeighbors({kind?: pets/people/all, areaId?, petType?: all/cat/dog/other, query?, cursor?, limit?})` 返回 `{items,nextCursor}`。默认 pets，people 指未公开宠物资料的主动参与者，不表示实际没有养宠。服务端按公开字段筛选并分页，排除自己、未加入/未核验、注销、屏蔽和目录展示账号。结果只含公共头像昵称、已公开宠物和简介、neighborArea、isFollowing、可选 distanceBand，不返回他人的住址、住宅网格、原生活片区、手机号或 OpenID。

本人 User 增加 `neighborVisible,neighborAreaId,residenceSharing,residenceCell,residenceUpdatedAt`。新开关默认 false，原 private area 不作为新公开区域。`residenceCell` 为 `neighbor-location.js` 生成的 `{grid,x,y}`，不接受原坐标/住址；双方同意时由服务端计算粗距离。开启需核验和有效公开片区，住宅设置限每 24 小时一次，关闭分享或退出可随时清除网格并保留限改时间；注销全部清除。宠物照片字段当前不支持，不能提交裸链接。

操作、隐私说明和上线验收见 [附近宠友与住宅距离](11-附近宠友与住宅距离.md)。
