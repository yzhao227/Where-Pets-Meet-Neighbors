# 分享可见范围

日期：2026-09-30。

## 使用

发布页在正文下方提供「可见范围」选择：

| 选项 | 谁能查看 |
| --- | --- |
| 公开 | 所有人，继续遵守已有屏蔽规则 |
| 仅好友可见 | 作者及已经双方确认、仍有效的好友；关注不等于好友 |
| 仅自己可见 | 只有作者 |

默认公开。旧内容、旧草稿没有范围字段时仍按公开处理；损坏的本机草稿范围保守恢复为仅自己可见。当前草稿会记住所选范围，清空草稿或发布完成后恢复默认值。

作者可以在详情的可见范围按钮或「更多 → 设置可见范围」修改已发布内容。「我的分享」标出非公开范围。修改失败保留原范围；其他人不能修改，管理员也没有普通浏览私密帖的豁免。所属圈子作为内容分类，不会扩大可见范围。

非公开内容隐藏平台分享菜单。即使回调被直接触发，也只返回应用首页、中性文案和固定公共封面，不带私人标题、正文或页面截图。

## 接口与访问控制

- `createPost` 增加 `visibility`，枚举为 `public`、`friends`、`private`；缺省为 `public`，非法输入拒绝。
- `setPostVisibility({ id, visibility })` 仅作者可调用，返回 `{ post }`；正常帖子投影返回 `post.visibility`。
- 云端与本机服务对发现、搜索、圈子、作者主页、收藏、详情、评论、点赞、收藏操作、消息正文与封面、可见数量及举报摘要应用相同权限。好友删除、屏蔽或范围收紧后，服务拒绝新的越权读取。
- 范围和好友关系变更会使当前客户端的发现列表缓存失效；普通浏览仍按第 15 份记录保留分页与位置。
- 已签名云媒体返回 `mediaSigned: true`，图片、视频或封面重试时重新鉴权、获取新地址。发布或范围修改已提交后，如果签名暂时失败，返回不含媒体的安全投影及 `mediaUnavailable: true`，避免误报失败导致重复发布。

## 云媒体部署要求

本轮没有部署真实云函数、存储规则或线上版本。本机演示可使用三种范围；云端私密媒体必须先完成下面的存储配置。

1. 依据 `infra/storage-policy.json` 为 `community/published/` 配置客户端 `read: false`、`write: false`，保持 `incoming/` 的本人上传规则和 `quarantine/` 的隔离规则。此文件是部署契约，不是可直接覆盖整个桶的微信规则文件。
2. 使用两个普通账号验证：即使知道文件 ID，也不能直接下载已发布媒体，或绕过业务接口自行获取临时地址。作者与合格好友通过业务接口正常读取，陌生人、待确认好友、单向关注及已移除好友不能读取受限帖子。
3. 确认规则和服务端临时 URL 能力后，设置业务云函数环境变量 `PUBLISHED_MEDIA_PRIVATE=true`。未确认时，非公开图片/视频的发布及范围修改返回 `PRIVATE_MEDIA_UNAVAILABLE`，不伪装为已保护；纯文字范围不受此门槛影响。
4. 服务先校验帖子或宠物资料权限，再签发地址，返回前再次检查访问权限。客户端帖子及消息投影不下发原始 `cloud://` ID。草稿图片、视频预览使用已保存的本机副本，提交仍用原始云文件 ID。
5. 当前适配器向平台请求 `maxAge: 60`，这不证明平台实际 60 秒失效。微信文档写明私有临时链接有效期为十分钟，部署时必须实测实际到期行为。收紧权限会立即拒绝新的授权链接，已经签发的链接可能继续有效到平台期限结束，已下载的副本也无法远程收回。

客户端与云函数需一同更新，旧客户端直接用已发布文件 ID 展示媒体的方式将不再可用。正式验收应包含新旧图片、视频、视频暂停后重试、公开宠物照片和草稿恢复。
