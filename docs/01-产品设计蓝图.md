# 有宠有邻｜产品设计蓝图

版本：规划稿 v0.4 · 更新：2026 年 9 月 29 日

配套文件：[里程碑落地计划](02-里程碑落地计划.md)

## 1. 产品方向与规划前提

产品定位：以宠物为共同兴趣，帮助爱宠人士建立持续关系，并逐步连接可信的本地服务与宠物消费。

品牌名：**有宠有邻**。品牌表达：**喜欢宠物，就在这里相遇。** 面向养宠人，也面向暂时没养宠的人；拥有宠物不作为参与门槛。孤独感是设计背景，产品提供可参与的日常、有人回应的交流和再次相遇的机会，不承诺治疗或消除孤独。

内容社区采用图文卡片、具体生活话题、点赞收藏、作者关注和活动关联，帮助用户从浏览兴趣走向持续交流。发现内容、获得实用信息、认识同好分别通过相应行为观察，不把浏览或点赞等同于建立关系。

已经确定的方向：

- 先验证内容、小圈子和交友带来的关系价值。
- 完整蓝图覆盖本地洗护、上门喂养、遛狗、宠物商品和商家入驻。
- 目前没有现成商家资源，需要在试运营中建立供给。
- 所有爱宠人士都保留完整的社区参与资格，宠物档案选填。

本轮规划采用的暂定条件：

- 先在一个城市的一个片区运营，城市和片区待选。
- 先做微信小程序，初期活动和举报管理内置小程序；独立网页后台随运营规模扩展。独立 App 在小程序已经证明价值、且出现明确能力需求后评估。
- 以精简团队推进：创始人负责产品及社区运营，1–2 名开发，设计和测试按需协作。实际人员、预算、资质准备情况尚未确认。
- 时间、样本和费率示例属于内部规划假设，不是行业标准、上线承诺或收益预测。

完整蓝图定义能力上限；每个版本只开放能够被运营和交付的部分。阶段编号代表建议投入顺序，各商业分支按自己的证据推进。

## 2. 三层价值与四类参与者

### 三层价值

| 层次 | 用户得到什么 | 平台需要证明什么 |
|---|---|---|
| 关系层 | 分享有人回应，认识合拍的人，逐渐进入稳定小圈子 | 互动能重复发生，用户愿意主动回来 |
| 生活层 | 更容易参加活动、找到可靠门店和照护帮助 | 信息准确、履约稳定、问题有人处理 |
| 经营层 | 在需要时购买合适的服务与商品 | 真实收费能覆盖成本，商家和用户愿意持续参与 |

### 四类参与者

| 角色 | 典型任务 | 平台提供的能力 |
|---|---|---|
| 爱宠人士 | 分享日常、找到同好、参加活动；有需要时消费 | 内容、小圈子、联系、活动、订单与售后 |
| 圈主／活动组织者 | 欢迎新人、组织话题和活动、延续关系 | 成员管理、活动名额、通知、取消、签到、活动记录 |
| 商家／服务团队 | 展示能力、接单、履约、处理售后、核对收入 | 经审核的身份、套餐及商品、档期库存、接单、账单 |
| 平台运营 | 维持内容和互动质量、经营供给、处理异常 | 审核、用户支持、订单干预、退款对账、经营分析 |

同一个账号可以有多个角色。用户是否养宠不决定其社区权限；商业身份清晰展示，参与活动或购买服务也不自动等于同意接收营销。

## 3. 稳定的信息架构

一级导航建议保持四个入口，随着阶段逐步增加内容，不在首版展示空白商城或无法接单的服务。

| 入口 | M1 社区首版 | 完整产品形态 |
|---|---|---|
| 社区 | 我的圈子、圈内动态、评论与话题 | 兴趣发现、创作者内容、共同记录、持续话题 |
| 附近 | 附近圈子、精选活动、公共集合点 | 活动、宠物友好地点、门店、洗护、上门照护、商品自提 |
| 消息 | 回复提醒、活动通知 | 双方同意的私聊、熟人小组、订单消息 |
| 我 | 兴趣、片区、可选宠物档案、参与记录 | 订单、收藏、护理记录、会员权益、组织者及商家入口 |

社区首页优先帮助用户继续已有互动，其次展示适合参与的新话题和活动。附近页按真实任务组织内容，例如“一起坐坐”“出门走走”“预约洗护”，各入口在供给就绪后开放。

商品初期位于门店详情和相关消费场景；当独立购物需求被证实后，再评估独立选购入口。

## 4. 完整板块设计

### A. 个人与宠物档案

- 个人资料包括昵称、兴趣、大致片区、希望参与的活动方式；精确定位授权可拒绝，允许手动选择片区。
- 宠物档案选填，包含种类、体型、性格和接触偏好。服务需要的健康、照护等资料在具体场景按需补充。
- 人和宠物是分开的主体：没有宠物的人能分享、发起话题、参加符合条件的活动；不适合出门的宠物可以在家。
- 后期保存用户授权的护理和服务记录，方便复约；记录不自动等于专业诊断或安全认证。

### B. 内容社区与小圈子

- 内容围绕爱宠日常、附近生活、经验交流和活动共同记录。
- 首版人工经营少量圈子，按实际兴趣与片区组织。一个圈子需要有负责接待新人的人、持续话题和行为规则。
- 动态可以关联圈子、活动，后期按需关联真实地点、商品或已完成服务。
- 为回复、再次参与和共同记录提供入口。推荐逐步考虑用户主动选择、实际互动和内容质量。
- 商家内容、合作推广与普通用户内容有明确身份标识；真实消费评价与普通社区讨论分别管理。

### C. 爱宠人士交友与宠物玩伴

爱宠人士的关系路径：共同话题 → 互相回应 → 固定圈子或共同活动 → 再次联系。

- M1 通过圈内评论和活动讨论相识，直接验证能否重复互动。
- M2A 增加双方同意的联系请求、私聊、熟悉伙伴列表和再次邀约。
- 人的推荐依据主要是兴趣、参与时间和场景偏好；不把“孤独程度”设为公开标签。
- 宠物玩伴作为独立子场景，参考体型、性格、活动强度和接触习惯。报名时展示牵引、交接和接触规则。
- 基础交流尽量保持容易使用。商业收费优先对应明确的组织、服务、商品或工具价值。

### D. 活动与共同经历

- 活动明确标注“无需带宠”“可带宠”或“需要带犬”，包括小聚、散步、交流和体验活动。
- M1 支持免费活动的介绍、人数、报名、取消、通知和讨论；运营可人工签到与回访。
- M2B 试点有明确交付的付费活动，补齐付款、退款、核销、组织方结算及逐场成本核算。
- 活动结束后形成用户自愿发布的共同记录，并允许再次邀请同一批人。
- 首次线下相识优先使用公开场所与小组活动。试运营中的线下陌生人活动建议先限定成年人；年龄政策在正式开放前确认。

### E. 本地生活服务

**到店洗护（M3）：**

- 门店信息、真实套餐、适用宠物条件、服务包含项、加价规则、可预约时段。
- 档期无法实时同步时采用“提交预约 → 商家确认时间及最终报价 → 用户付款”。
- 完成服务后核销，支持取消、改期、退款申请、评价、再次预约和客服介入。
- 商家最小接单入口在该阶段同时提供，不能依赖平台长期代替商家确认所有订单。

**上门喂养（M5A）：**

- 明确服务团队和具体服务人员、照护任务、时间窗口、入户授权、宠物情况、紧急联系人。
- 记录到达、任务执行、必要照片及结束；入户地址、钥匙和门禁信息按履约需要限制访问。
- 有取消、人员替换、无法入户、宠物异常和延误的实际处理流程。

**遛狗（M5B）：**

- 明确宠物性格、牵引装备、交接方式、活动时间和允许的接触方式。
- 建立出发、途中异常、归还确认和应急处理流程。
- 路线和实时位置仅在必要的订单参与者之间授权展示，不公开成为社交地图。

喂养和遛狗分别选团队、试单、验收。到店洗护的成功不能代替入户和交接服务的专门准备。

### F. 宠物商品

- M4 先由合作商家供货，选择少量有真实需求的用品；平台暂按撮合与交易服务模式规划，不默认自营囤货。
- 商品展示来源、规格、价格、库存和适用信息；涉及效期的商品展示相应资料。
- 初期每单一家门店，以到店自提为主，具备提货凭证和退换货处理。
- 服务预约和商品销售有独立履约状态、售后规则；共享账号及支付基础，但不混成一个笼统的完成状态。
- 配送作为独立扩展试点，补齐运费、发货时效、物流、破损丢件和退货成本，再评估扩大。

### G. 商家与组织者经营能力

- M0 起可以访谈潜在合作方，记录需求；这不代表已经具备可售供给。
- M3 以邀请制审核门店，人工帮助整理资料，同时提供接单、档期、核销、退款协同和账单入口。
- M4 扩展商品库存、订单管理、经营数据和申请审核流程；达到审核及客服能力后再逐步开放自助申请。
- M5 增加服务团队、人员、可服务区域和任务记录管理。
- M6 依据商家真实付费意愿测试经营工具订阅与标识明确的商业展示。付费展示不改变真实评价与投诉处理。

### H. 信任、治理和经营基础

以下能力从首版开始，随规模持续投入：

- 内容审核、举报、拉黑、权限控制、账号及内容删除申请、客服和事件记录。
- 用户资料按场景最少收集；圈子、活动、订单、营销有独立的信息使用边界。
- 组织者、商家、服务人员的身份和核验范围明确展示；主人自述与平台核验记录分别标识。
- 首次收费前确认交易责任方、收款退款和结算方案、合作协议及客服责任。正式上线时核对所用平台的当前主体、类目、支付和资质要求。
- 每笔付款、退款、核销与结算可核对；商家申请、退款、资料导出等操作有权限和记录。
- 避免为了经营指标而强制公开私人情绪、位置、社交关系或宠物健康资料。

## 5. 五条完整用户旅程

| 场景 | 产品路径 | 成功结果 |
|---|---|---|
| 暂时没养宠，也想认识爱宠朋友 | 选兴趣与片区 → 加入圈子 → 互相回复 → 无需带宠的小聚 → 再次联系 | 用户作为圈子成员持续参与 |
| 养猫但不方便带猫出门 | 分享日常 → 参与猫主人及爱猫者话题 → 主人交流活动 → 固定小圈子 | 通过共同兴趣获得持续回应 |
| 想找合适的遛狗伙伴 | 选择时间与片区 → 查看活动及接触规则 → 确认宠物适配 → 同行 → 再约 | 人和宠物的互动都合适、可重复 |
| 需要可信的洗护与用品 | 查看真实门店及套餐 → 确认预约 → 付款服务 → 核销及评价 → 按需要买同店商品 → 复约 | 服务完成、成本透明、再次消费有理由 |
| 临时需要照护 | 查看审核团队 → 提交任务与必要资料 → 确认服务人和规则 → 付款 → 服务记录与交接 → 售后或复订 | 照护按约定完成，异常有明确处理人 |

## 6. 版本总览与依赖

| 阶段 | 主要发布内容 | 商业安排 |
|---|---|---|
| M0 人工验证 | 首批成员、少量圈子、固定活动、用户和供给访谈 | 记录成本与需求 |
| M1 社区首版 | 资料、图文评论、圈子、免费活动、通知、治理后台 | 验证持续关系 |
| M2 关系与体验 | M2A 双向联系和再次邀约；M2B 付费活动 | 按明确交付试收活动费用 |
| M3 到店服务 | 洗护预约、付款、核销、退款、最小商家入口 | 完成订单后的约定佣金 |
| M4 商品与商家 | 精选商品自提、退换货、库存、商家工作台与申请审核 | 商品成交佣金；配送另行试点 |
| M5 上门服务 | M5A 喂养；M5B 遛狗；人员、任务、交接和异常处置 | 分类别服务佣金或约定服务收入 |
| M6 盈利与复制 | 区域经营、复购、获客效率，按需测试会员与商家工具 | 扩大已成立的收入组合 |

依赖按能力判断：

1. 社区基础支撑关系增强；内容供给、审核和用户支持在每一阶段持续进行。
2. 明确需求、可靠供给和交易基础，共同支撑付费活动、到店服务或商品试点。付费活动盈利不是洗护上线的前置条件。
3. 上门喂养和遛狗额外依赖人员、交接和异常处理能力，两个类别分别放行。
4. 区域复制以核心体验和选定收入组合稳定为条件，不要求先做完全部板块。

全量板块都有实施位置；尚未成立的分支保留小规模试验，已满足条件的分支可在资源允许时继续。

## 7. 收入模型与赚钱效应

### 收入来自哪项交付

| 收入类型 | 平台需要实际交付 | 何时验证 |
|---|---|---|
| 活动组织收入 | 活动策划、场地协调、主持与参与体验 | M2B |
| 本地服务佣金 | 可追踪成交、预约协调、必要的交易与售后服务 | M3、M5 |
| 商品佣金 | 有购买理由的商品供给、成交、提货及售后支持 | M4 |
| 会员权益 | 用户真正会使用、成本可核算的权益或工具 | M6，需求成立时 |
| 商家工具订阅 | 能节约工作或改善经营、值得商家付费的工具 | M6，商家验证后 |
| 商业展示 | 明确标识的曝光和可评估的推广价值 | 有稳定使用与审核能力后 |

早期采用低门槛合作、完成订单后按约定收费。洗护、商品和上门服务按各自毛利、工作量与责任分配协商，不能默认统一费率。

### 经营口径

- **成交额：**用户购买服务和商品的金额。
- **平台归属收入：**平台按业务模式实际取得的佣金、组织服务收入、工具或权益收入；代收且归商家的部分不作为平台收入。
- **单笔贡献：**平台归属收入减去平台承担的支付、优惠、直接履约、退款净损失、直接客服等变动成本。
- **区域经营贡献：**区域内各业务贡献之和，减去该区域获客费用与固定运营费用。
- **整体经营结果：**区域经营贡献之和，再减去尚未分摊的产品开发、管理、工具等公共固定成本。成本归集一次，避免重复扣算。

活动票款是否全部作为平台收入，取决于平台自营还是向组织者收取服务费，需要按实际合同和会计口径确定。

演示算账：假设一单 100 元、平台佣金 10%、平台承担变动成本 5 元，则每单贡献 5 元。假设获取该用户花费 25 元，在每单贡献不变且用户实际复购的前提下，需要 5 笔这样的完成订单覆盖该次获客成本，仍未覆盖固定成本。以上数字仅用于解释，不代表预计业务表现。

### 逐步提升收益的顺序

1. 先提高按约履约和体验，减少拒单、取消、加价争议及售后损失。
2. 让满意用户容易复约，按真实消费周期做用户主动选择的提醒。
3. 对已经出现的需求提供相关商品或服务，提高有效购买，观察是否增加售后成本。
4. 通过已有小圈子、口碑、活动及商家合作改善获客效率，分别核算渠道。
5. 在商家愿意持续合作的条件下优化收费和服务结构。
6. 将核心体验和经营贡献稳定的组合复制到相邻片区，再评估扩大地域。

从第一笔收费开始记录成本；M6 负责扩大已验证的经营效果，不把盈利核算留到最后。

## 8. 判断产品是否在变好

保留一组关系指标和一组经济指标，同时观察质量约束。

| 维度 | 主要观察 | 解释与边界 |
|---|---|---|
| 新人体验 | 首次发言是否得到实质回应、首次活动能否顺利参与 | 区分运营回复和普通用户回复 |
| 关系延续 | 与同一用户或同一小组再次互动、再次参与 | 点赞和单次到场不能单独代表关系成立；结合自愿回访 |
| 包容性 | 未养宠用户的参与、复联和回访反馈 | 按是否养宠分组检查，不增加参与门槛 |
| 自发活力 | 用户发起的话题、邀约及组织行为 | 看对运营持续推动的依赖是否降低 |
| 交易质量 | 确认速度、完成率、退款原因、投诉及处理时间 | 分品类、商家与实际可履约条件观察 |
| 经营收益 | 单笔贡献、用户批次累计贡献、复购、获客成本、固定成本 | 成交额增加时也可能亏损扩大 |
| 关系质量 | 回访中的实际结识与持续联系 | 用户在其他工具中继续联系也可能兑现产品价值 |

具体统计定义、首轮内部试验目标和各阶段验收见配套落地计划。样本不足时扩大观察，而不是将短期好看的数字当作规模化证据。

## 9. 资源配置与运行边界

| 工作 | 首期责任 | 随业务扩大增加的职责 |
|---|---|---|
| 产品与经营判断 | 创始人 | 品类负责人、区域经营负责人 |
| 社区和活动 | 明确的社区运营负责人；早期可由创始人兼任 | 圈主支持、活动组织及质量管理 |
| 开发、设计与测试 | 精简开发团队，设计与测试协作 | 根据真实使用瓶颈补充，而非预建全部系统 |
| 商家及供应管理 | M0 开始访谈，M3 形成明确负责人 | 类别、库存、服务团队与质量管理 |
| 审核、客服和售后 | M1 有可联系的人与处理记录 | 首次收费起明确退款与纠纷权限，上门服务需应急响应 |
| 财务与交易核对 | 首次收费前确定责任与方案 | 逐笔核对、按业务及区域看账、管理结算 |

增加板块前，负责人要能说明新增的用户价值、真实供给、运营投入、单笔收益及最差情况下的处置办法。每月复盘已经开放的能力，关闭无供给的入口、修正异常流程、调整小规模试点。

下一步从 M0 执行清单开始：选择片区、访谈不同养宠状态的用户、招募首批成员、组织重复参与机会，并记录真实反馈。M1 的详细页面与验收条件已在落地计划中展开。


## v0.3：后台核验与宠物名片

采用后台核验、前台昵称的账号设计。用户可以先浏览，在互动时阅读协议、主动同意并完成核验；当前本机版只提供明确标识的模拟流程，正式微信手机号核验待账号与平台能力接入。OpenID 仅用于识别账号，不表示真实身份已经核验。

首版宠物档案选填、每个账号最多一只，暂未养宠的人同样可以参与。主页资料公开与头像旁宠物名片分别设置，默认关闭；旧版主页授权不会自动扩大到公开署名。管理员可查看登记份数及猫／狗／其他分类汇总，未填写资料不能推断为没有宠物。手机号不进入公共内容或运营统计。具体流程见 [注册与资料可见范围](05-注册与资料可见范围.md)。
