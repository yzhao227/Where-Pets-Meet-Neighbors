## 本轮设计方案

目标是让“宠物、照片、内容”先被看见，让个人信息和设置更容易阅读。沿用既有暖白与珊瑚色，不改变应用框架和业务范围。

### 颜色与字体

| 用途 | 色值 |
| --- | --- |
| 页面暖白 | `#FAF8F5` |
| 卡片白 | `#FFFFFF` |
| 主要文字 | `#24262D` |
| 辅助文字 | `#6A717B` |
| 主要操作 | `#CC4A37` |
| 浅色分隔 | `#E9E5E1` |

继续使用系统中文字体（PingFang SC 等）。标题约 20–24px，正文 14–16px；字号随小程序 rpx 换算，重要按钮触区至少 44px。强调色集中用于主要操作和选中状态，照片提供页面色彩。

### 页面布局

1. **我的**：页标题 → 紧凑的用户身份区 → 独立宠物卡 → 分享/收藏等常用入口 → 草稿及其他功能 → 账号、隐私与帮助。宠物照片大于主人头像；无宠物时显示真实的添加入口，不使用假宠物或假统计填充。
2. **宠物档案**：宠物资料与照片优先 → 个人资料 → 公开范围与其他设置。放大照片，表单分组清楚，保留选填说明、保存状态和上传失败重试。
3. **发现**：品牌栏 → 内容导航与发布 → 搜索和筛选 → 双列图文。照片承担主要视觉，减少卡片边框和装饰，保留清楚的标题、作者与操作触区。

### 实施前复核

- 突出宠物依靠真实照片、顺序和尺寸，不添加装饰性 hero、口号或虚构推荐。
- 默认账号可能没有宠物；空状态仍要自然、可操作，避免巨大的空照片框。
- 中文标题与长宠物名应可换行；顶部标题避开微信胶囊，底部操作避开 tabBar 与安全区。
- 保留草稿、照片重试、资料可见范围、原个人版私人资料库与清理保护；不恢复已移除的视频或群聊。
- 页面样式局部覆盖，避免影响附近、私信、发布等未改版页面。

## 后续复用方式

对后续 UI 任务，可使用这样的说明：

> 先读取 `docs/19-UI工具与设计规范.md`，按 frontend-design 完成有宠有邻的原生小程序 UI。沿用暖白与珊瑚色，让宠物照片和主要内容突出。组件库仅按需参考，保留页面行为及隐私设置。完成后检查窄屏、空状态、微信模板编译与相关行为测试。

验证记录及截图保存在对应的 `output/` 交付记录中。浏览器预览用于视觉与交互检查，微信真机仍需确认原生选图、胶囊、安全区及真实接口表现。
