# 有宠有邻 · 喜欢宠物，就在这里相遇

分享和宠物一起的日常，与宠友交流，浏览养宠资料、宠物友好地点与公开活动资讯。

当前源码为 **v0.5.0 的文字图片修订版（本地修改，尚未重新上传）**。用户于2026年10月22日反馈此前审核被驳回并要求移除视频；本轮已取消视频发布和播放，历史视频从目录、列表、详情及发布包中下架。点击“+”直接进入文字/图片编辑页。按用户2026年10月20日的新要求，配置切为 `productMode: 'community'`，恢复公开发帖、微信转发与朋友圈、评论、点赞和关注。当前分类入口为主题指南，一对一交流以留言呈现，群聊入口与操作已下线。仍为 `mode: 'demo'`、空 `cloudEnv`：本机可验证页面和流程，跨设备发帖、留言及用户媒体共享尚未连接真实云服务。产品范围固定在代码包中，不根据审核身份、时间或远程开关变化。

**截至2026-10-21最后一次后台核对，微信线上为0.4.2个人工具版，发布时间为2026-10-20 19:02:17；0.5.0于2026-10-21 17:33:26按用户指定备注重新上传，随后提交审核；用户随后反馈审核被驳回，文字图片修订尚未重新上传。** 审核提交成功不等于审核通过；本版发帖和留言仍为本机演示，真实云服务尚未部署。详见[0.5.0上传与提审记录](output/wechat-community-0.5.0-upload-20261021.md)。真实多人服务仍需按实际功能接通云环境并完成微信真机验收，相关主体类目与能力要求以微信平台实际审核为准。

发现页展示随代码维护的知识和图片资料，包括多图和多个动物种类。数量与构建就绪情况以 `npm run content:status` 的实际输出为准；本机导入不代表微信线上更新。

出行页使用独立的公共地点与活动目录，支持搜索、区域和玩法筛选、携宠规则、日期筛选、实景图、路线攻略、主动定位或手选参照，以及公共目的地导航。定位能否使用取决于微信接口权限和用户授权；缺少已核实坐标时不编造距离。参考资料、携宠条件和时效说明在详情查看，边界见 [附近导航与原文跳转](docs/14-附近导航与原文跳转.md)。

## 现在就能体验

电脑安装 Node.js 22.13 或更新版本（推荐 24）后，在项目根目录运行：

```sh
npm run dev
```

打开 [有宠有邻本机体验](http://127.0.0.1:4173)。本机体验没有第三方依赖，不需要先运行 `npm install`。服务运行期间保持终端打开；按 `Ctrl+C` 停止服务。

浏览器体验使用小程序的页面逻辑、模板、样式和本机社区数据服务，方便检查页面与操作。演示核验、演示留言与演示发布均只保存在当前设备；微信原生选图、持久文件、定位和分享仍需在开发者工具与真机中验证。

## 可用功能

| 板块 | 功能 |
| --- | --- |
| 内容发现 | 开发者维护的图文资料；主题与动物种类筛选、种类隐藏、标题/正文/话题搜索 |
| 日常分享 | 文字、最多 3 张照片；新记录默认公开，旧草稿保留原范围，可关联地点与到访 |
| 附件与草稿 | 本机保存所选照片；隔离保存草稿，支持失败重试、移除与恢复；旧视频草稿只保留清理入口 |
| 收藏与到访 | 私人内容收藏、地点收藏与管理、到访备注，不对其他用户展示 |
| 出行 | 公共地点和主办方公开活动；近期、往期、月份预告分开；实景图、距离参照与公共目的地导航 |
| 我的 | 资料与公开范围、宠物档案及照片、我的分享、收藏及本机私人资料库 |
| 留言与主题 | 作者主页发起一对一文字留言，消息页统一汇集通知与留言，“留言”入口同时收纳内容评论、回复和一对一留言；按养宠主题浏览内容，保留关注和举报/屏蔽；当前为本机演示流程，群聊入口与操作已下线，历史数据保留 |
| 微信分享 | 公共首页、地点、活动、公开帖子和主页支持好友及朋友圈入口；非公开帖子由作者主动公开后再分享 |

原个人版保存的日记、宠物资料和草稿通过“我的 → 本机私人资料”查看，不自动迁移到社区或公开。社区新内容仍遵守作者选择的可见范围；资料编辑页面不直接转发，公开主页只展示允许公开的字段。转发使用公共封面，不把本人私密信息或编辑中的草稿截入卡片。

社区设计与实现记录见 [注册与资料可见范围](docs/05-注册与资料可见范围.md)、[附近宠友与住宅距离](docs/11-附近宠友与住宅距离.md)、[媒体地点与宠物资料验收](docs/13-媒体地点与宠物资料验收.md) 和 [附近投稿与审核](docs/16-附近投稿与审核.md)。这些能力尚未同步到微信线上0.4.2。

外部展览与活动不创建站内报名、名额或付费订单。只有月份的官方预告不显示成已确定日期的近期活动；往期内容明确标记已结束。地点携宠条件未知时不进入“带宠出门”。实景图的来源与许可按图保留，需署名的素材在详情资料区展示；照片不代表当前入场规则或展讯。更多坐标、入口及信息时效仍需持续核实。

## 主题和动物筛选

底层保留8个圈子分类；发现页的“主题”入口打开主题指南，按养宠主题浏览内容。内容话题与动物种类筛选继续保留。

8 个主题用于描述内容：饮食喂养、行为观察、健康护理、居家布置、户外出行、成长记录、治愈瞬间、陪伴日常。主题不再重复“猫”“狗”等圈子或动物名称；旧主题会映射到当前值并去重。

动物标签独立于圈子和主题。用户可只看某类动物，也可隐藏不想看的种类；未标注内容单独提供入口。猫狗同框应同时标注猫、狗，隐藏其中任一类会排除该内容。寄居蟹使用 `invertebrate`（无脊椎动物），不会归入鱼或爬行动物。枚举分别由 `miniprogram/data/circles.js`、`topics.js`、`animal-types.js` 维护。

## 本轮内容与展示账号

知识卡从已核实的 ASPCA 资料中筛选，使用独立中文摘要；图片采用逐项核实的 CC0 或 Public Domain 素材。包括知识卡配图在内，当前展示素材不要求公开署名，因此普通页面不再显示“资料整理”“授权图片”“作品来源”及摄影署名块。

原始文章、素材详情、作者和许可元数据、文件摘要、修改说明与复核记录继续保留。隐藏页面上的署名不等于删除来源证据，也不改变旧素材的许可。来源与维护规则见 [内容来源与维护](docs/07-内容来源与维护.md)，导入步骤见 [首批内容执行计划](docs/09-首批300条内容执行计划.md)。

历史内容目录保留六个展示账号的来源元数据：橘子与猫、奶盖喵、栗子汪汪、阿禾慢慢遛、毛球笔记、毛孩拾光。它们不代表真实社区用户；演示操作不代表有人真实互动或回复。

旧目录撤下的知识及猫狗内容保存在 `content/batch-001/withdrawn-*.json`，原始素材不因撤下而删除。目录同步保留用户自己的账号、帖子、草稿和互动；已删除目录项不会因更新恢复。知识卡引用现有照片作封面，不增加图片内容的条目数。

```sh
npm run content:status
npm run content:validate
```

当前目录清单为 `content/batch-001/approved.json`，新采集材料在 `content/batch-002/`。构建目标读取清单的 `targets`，当前为 `{knowledge: 58, photo: 289, video: 0}`。`content:build` 要求数量与目标一致且全部审核通过；`content:publish` 允许不超过目标的非空小批清单。**两种命令均替换完整本机目录，清单必须包含所有仍要展示的条目。** 它们不会上传微信或写入云数据库。

附近地点和活动资讯维护于 `miniprogram/data/nearby-catalogue.js`，不走社区素材的构建清单。来源查阅、去重与更新记录保存在 [附近研究记录](output/nearby-research/)，目录数量随维护变化。修改本地目录不会自动发布到微信线上；当前仍需重新构建、上传并完成审核发布，才能让线上版本使用新目录。

## 导入微信开发者工具

1. 本地开发可导入项目根目录，即包含 `project.config.json` 的文件夹。
2. 使用该小程序管理员或已添加开发者的微信登录开发者工具。
3. 当前本地验证使用 `miniprogram/config.js` 的 `productMode: 'community'`、`mode: 'demo'` 和空 `cloudEnv`；真实服务部署完成前不要把本机演示当成多人版本。
4. 更新后重新编译；无需为了刷新目录清除用户缓存。

历史个人版的独立候选包构建命令仅适用于完整个人版配置，当前社区配置会被该命令拒绝：

```sh
npm run release:personal -- artifacts/wechat-personal-candidate
```

输出目录必须尚不存在，并需安装微信开发者工具以运行离线编译检查。该历史构建器生成文件摘要清单，**仅生成本地包，不上传、部署或提交审核**。不要为重新上传而改写已发布0.4.2候选目录。

目前资料、媒体与演示操作只保存在当前浏览器或设备，不与其他人同步。原个人版独立存储继续保留；社区清理不得误删其草稿或仍被引用的本机附件。公开资讯和素材加载仍可能使用网络。

## 社区云服务接入

恢复社区功能不改变线上已审核的个人版。真实服务应按恢复后的产品范围接入并完成平台验收。接入资料见 [初版使用与接入指南](docs/04-初版使用与接入指南.md)、[云开发接入说明](cloudfunctions/community/README.md) 和 [部署基础说明](infra/README.md)；`npm run release:plan` 用于检查部署条件。

云端源码已实现业务和权限检查，但尚未部署。正式手机号核验和图片上传需要真实平台能力、配置及验证；本机成功不代表云端能力已开通。云端连接失败会显示错误，不会静默切回演示数据。

真实图片支持同步检查或带微信签名/AES 加密回调的异步检查，审核失败时不会发布。 **当前发布包固定禁用视频选择、上传、发布和播放。** 旧视频数据不再对外展示；用户原存储与草稿保留，历史视频素材只在开发目录归档，不进入新代码包。保留的云端视频审核设计见 [历史视频上传接入说明](docs/video-upload.md)，不代表当前产品已启用该能力。

图片托管地址、合法域名、云存储规则、真机媒体加载和多人互动仍需分别验收。0.4.1 开发版上传不代表完成云端内容发布、多人服务部署或正式小程序发布。

## 检查与测试

```sh
npm run check
npm test
npm run content:validate
# 已安装微信开发者工具时：
npm run check:wechat
```

`npm test` 依次运行当前社区版和保留私人资料的隔离回归。个人模式仅在独立进程内使用内存测试配置，不修改交付配置或真实用户存储。检查覆盖页面、私人数据兼容、目录同步、权限、审核、上传与部署流程。SQLite仅用于社区测试适配，生产后端面向CloudBase。

历史验收记录见 [功能验收记录](docs/06-功能验收记录.md)，已发布个人版的历史交付范围见 [0.4.2 交付记录](output/wechat-personal-0.4.2-20261014.md)，当前社区恢复情况见 [0.5.0 本地交付记录](output/community-0.5.0-restore-20261020.md)；结果以本次实际命令输出为准，不在此固定测试数量或包体大小。

`check:wechat` 使用已安装开发者工具的 `wcc/wcsc` 检查模板和样式，不上传代码。非默认安装位置可用 `WECHAT_COMPILER_DIR` 指向 `wcc-exec` 目录。离线编译、浏览器预览和开发者工具模拟器均不能替代真机、真实云环境与微信接口验收。
