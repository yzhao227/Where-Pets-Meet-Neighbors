# 有宠有邻 · 喜欢宠物，就在这里相遇

记录和宠物一起的日常，浏览养宠资料、宠物友好地点与公开活动资讯。

当前源码为 **v0.4.2 个人工具版**，配置固定为 `productMode: 'personal'`、`mode: 'demo'`，云服务关闭。私人日记、宠物档案、收藏与到访记录仅保存在当前设备。社区源码和部署工具保留供未来独立版本使用，不属于当前交付功能，也不会随审核状态自动恢复。

**微信开发版 0.4.1 已于 2026-10-14 上传，0.4.2 已于 2026-10-20 上传；均未提交审核或公开发布。** 详见 [0.4.1 上传记录](docs/18-微信开发版上传记录.md)、[0.4.2 个人工具版交付记录](output/wechat-personal-0.4.2-20261014.md) 和 [0.4.2 开发版上传记录（2026-10-20）](output/wechat-personal-0.4.2-upload-20261020.md)。上传记录对应当时的候选快照，仓库后续修改需另行构建与上传；本地验证不代表已完成微信真机验收。

发现页展示随代码维护的知识、图片及短视频资料，包括多图和多个动物种类。数量与构建就绪情况以 `npm run content:status` 的实际输出为准；本机导入不代表微信线上更新。

附近页使用独立的公共地点与活动目录，支持搜索、区域和玩法筛选、携宠规则、日期筛选、实景图、路线攻略、主动定位或手选参照，以及公共目的地导航。定位能否使用取决于微信接口权限和用户授权；缺少已核实坐标时不编造距离。参考资料、携宠条件和时效说明在详情查看，边界见 [附近导航与原文跳转](docs/14-附近导航与原文跳转.md)。

## 现在就能体验

电脑安装 Node.js 22.13 或更新版本（推荐 24）后，在项目根目录运行：

```sh
npm run dev
```

打开 [有宠有邻本机体验](http://127.0.0.1:4173)。本机体验没有第三方依赖，不需要先运行 `npm install`。服务运行期间保持终端打开；按 `Ctrl+C` 停止服务。

浏览器体验使用小程序的页面逻辑、模板、样式和个人版本机数据服务，方便检查页面与操作。微信原生选片、持久文件、定位和视频播放仍需在开发者工具与真机中验证。

## 可用功能

| 板块 | 功能 |
| --- | --- |
| 内容发现 | 开发者维护的图文、视频资料；主题与动物种类筛选、种类隐藏、标题/正文/话题搜索 |
| 私人日记 | 文字、最多 3 张照片或 1 个视频；可关联地点与到访，仅自己在本机查看 |
| 附件与草稿 | 本机保存所选照片和视频；隔离保存草稿，支持失败重试、移除与恢复 |
| 收藏与到访 | 私人内容收藏、地点收藏与管理、到访备注，不对其他用户展示 |
| 附近 | 公共地点和主办方公开活动；近期、往期、月份预告分开；实景图、距离参照与公共目的地导航 |
| 我 | 私人资料、宠物档案及照片、私人记录、收藏与本机资料清除 |

当前版本不提供用户公开发布、微信转发或朋友圈分享、评论、点赞、关注、圈子、聊天、附近宠友、住宅距离、用户活动报名、投稿审核或手机号核验。相关旧页面与接口入口均受个人版范围限制。

保留的社区设计与实现记录见 [注册与资料可见范围](docs/05-注册与资料可见范围.md)、[附近宠友与住宅距离](docs/11-附近宠友与住宅距离.md)、[媒体地点与宠物资料验收](docs/13-媒体地点与宠物资料验收.md) 和 [附近投稿与审核](docs/16-附近投稿与审核.md)。这些文档中的社区功能及云端流程不代表个人版已开放。

外部展览与活动不创建站内报名、名额或付费订单。只有月份的官方预告不显示成已确定日期的近期活动；往期内容明确标记已结束。地点携宠条件未知时不进入“带宠出门”。实景图的来源与许可按图保留，需署名的素材在详情资料区展示；照片不代表当前入场规则或展讯。更多坐标、入口及信息时效仍需持续核实。

## 主题和动物筛选

社区源码保留 8 个圈子的分类定义，当前个人版不提供圈子入口或社群交流。

8 个主题用于描述内容：饮食喂养、行为观察、健康护理、居家布置、户外出行、成长记录、治愈瞬间、陪伴日常。主题不再重复“猫”“狗”等圈子或动物名称；旧主题会映射到当前值并去重。

动物标签独立于圈子和主题。用户可只看某类动物，也可隐藏不想看的种类；未标注内容单独提供入口。猫狗同框应同时标注猫、狗，隐藏其中任一类会排除该内容。寄居蟹使用 `invertebrate`（无脊椎动物），不会归入鱼或爬行动物。枚举分别由 `miniprogram/data/circles.js`、`topics.js`、`animal-types.js` 维护。

## 本轮内容与展示账号

知识卡从已核实的 ASPCA 资料中筛选，使用独立中文摘要；图片和视频采用逐项核实的 CC0 或 Public Domain 素材。包括知识卡配图和视频封面在内，本轮素材不要求公开署名，因此普通页面不再显示“资料整理”“授权图片”“作品来源”及摄影署名块。

原始文章、素材详情、作者和许可元数据、文件摘要、修改说明与复核记录继续保留。隐藏页面上的署名不等于删除来源证据，也不改变旧素材的许可。来源与维护规则见 [内容来源与维护](docs/07-内容来源与维护.md)，导入步骤见 [首批内容执行计划](docs/09-首批300条内容执行计划.md)。

历史内容目录保留六个展示账号的来源元数据：橘子与猫、奶盖喵、栗子汪汪、阿禾慢慢遛、毛球笔记、毛孩拾光。它们不代表真实社区用户；当前个人版不提供作者社交主页或用户互动。

旧目录撤下的知识及猫狗内容保存在 `content/batch-001/withdrawn-*.json`，原始素材不因撤下而删除。目录同步保留用户自己的账号、帖子、草稿和互动；已删除目录项不会因更新恢复。知识卡引用现有照片作封面，不增加图片内容的条目数。

```sh
npm run content:status
npm run content:validate
```

当前目录清单为 `content/batch-001/approved.json`，新采集材料在 `content/batch-002/`。构建目标读取清单的 `targets`，当前为 `{knowledge: 58, photo: 289, video: 13}`。`content:build` 要求数量与目标一致且全部审核通过；`content:publish` 允许不超过目标的非空小批清单。**两种命令均替换完整本机目录，清单必须包含所有仍要展示的条目。** 它们不会上传微信或写入云数据库。

附近地点和活动资讯维护于 `miniprogram/data/nearby-catalogue.js`，不走社区素材的构建清单。来源查阅、去重与更新记录保存在 [附近研究记录](output/nearby-research/)，目录数量随维护变化。修改本地目录不会自动发布到微信线上；当前个人版需重新构建、上传并完成审核发布，才能让线上版本使用新目录。

## 导入微信开发者工具

1. 本地开发可导入项目根目录，即包含 `project.config.json` 的文件夹。
2. 使用该小程序管理员或已添加开发者的微信登录开发者工具。
3. 保持 `miniprogram/config.js` 的 `productMode: 'personal'`、`mode: 'demo'` 和空 `cloudEnv`。
4. 更新后重新编译；无需为了刷新目录清除用户缓存。

生成用于上传的独立个人版候选包：

```sh
npm run release:personal -- artifacts/wechat-personal-candidate
```

输出目录必须尚不存在，并需安装微信开发者工具以运行离线编译检查。构建会排除停用的社交目录和云函数，生成文件摘要清单；随后在开发者工具中导入候选目录下的 `project.config.json`。**该命令仅生成本地包，不上传、部署或提交审核。**

私人资料、媒体与操作只保存在当前浏览器或设备，不与其他人同步。历史社区存储保持只读，新日记与草稿使用独立存储；可以读取本人的历史记录作为私人内容，不会将其公开。公开资讯和素材加载仍可能使用网络。

## 保留的社区源码与部署说明

以下说明仅适用于未来独立的社区版本，不是当前个人工具版的上线步骤。相关能力需要另行明确产品范围、具备所需资质并完成平台验收，不会在个人版审核后自动启用。历史接入资料见 [初版使用与接入指南](docs/04-初版使用与接入指南.md)、[云开发接入说明](cloudfunctions/community/README.md) 和 [部署基础说明](infra/README.md)；`npm run release:plan` 用于检查这些部署条件。

云端源码已实现业务和权限检查，但尚未部署。正式手机号核验、图片上传与用户视频上传都需要真实平台能力、配置及验证；本机成功不代表云端能力已开通。云端连接失败会显示错误，不会静默切回演示数据。

真实图片支持同步检查或带微信签名/AES 加密回调的异步检查，审核失败时不会发布。**用户视频云上传默认关闭，必须接入能审核完整视频及音轨的真实 provider；图片审核不能替代视频审核，仅填写环境变量也不能开启。** 视频暂限 60 秒、20 MiB，详见 [视频上传与审核接入](docs/video-upload.md)。人工复核的预置视频与用户上传审核能力分别管理。

图片托管地址、合法域名、云存储规则、真机媒体加载和多人互动仍需分别验收。0.4.1 开发版上传不代表完成云端内容发布、多人服务部署或正式小程序发布。

## 检查与测试

```sh
npm run check
npm test
npm run content:validate
# 已安装微信开发者工具时：
npm run check:wechat
```

`npm test` 依次运行“当前个人工具版”和“保留社区源码的隔离回归”两组测试。社区测试仅在独立进程内使用测试配置，不修改交付配置或真实用户存储。检查覆盖个人版页面与本机保存、目录同步，以及保留源码的权限、审核、上传与部署流程。SQLite 仅用于社区测试适配，保留的生产后端面向 CloudBase。

历史验收记录见 [功能验收记录](docs/06-功能验收记录.md)，当前个人版交付范围见 [0.4.2 交付记录](output/wechat-personal-0.4.2-20261014.md)；结果以本次实际命令输出为准，不在此固定测试数量或包体大小。

`check:wechat` 使用已安装开发者工具的 `wcc/wcsc` 检查模板和样式，不上传代码。非默认安装位置可用 `WECHAT_COMPILER_DIR` 指向 `wcc-exec` 目录。离线编译、浏览器预览和开发者工具模拟器均不能替代真机、真实云环境与微信接口验收。
