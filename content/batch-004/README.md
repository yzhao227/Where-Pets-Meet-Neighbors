# 新增 100 条多图与视频

本批已加入 **100 条非知识内容：92 组图片、8 条视频**。完整目录由 260 条增至 **360 条**，组成是 58 条知识内容、289 条图片内容、13 条视频。原 260 条的 manifest 与运行对象分别保存在 `baseline-260.json`、`baseline-runtime-260.json`，已逐条深比较确认没有改动。

92 组图片使用 **150 张此前未发布的独立原片**，以及 35 次有明确引用的原图配图（33 张不同原图）。每组有 2–3 张图片，至少一张是真正新原片；没有将两张旧图拼成新条目。全部 150 张新图片采用 CC0，逐图保留来源页面、作者、许可、原元数据与实际下载副本。候选中的标本、解剖图、AI 插画、地名误命中、旧原图的裁剪变体、坏文件和明显低质图片均未采用。

猫狗合计 16%。其余包括仓鼠、豚鼠、虎皮鹦鹉、玄凤及多种牡丹鹦鹉、守宫、鬃狮蜥、玉米蛇、球蟒、陆龟与水龟、美西螈、虾、金鱼、斗鱼、孔雀鱼和恩德勒孔雀鱼等。另有真实水族店与鱼池场景。来源不足以确认具体物种的水族与龟类照片保留普通画面描述，不作为新物种数量依据。

组图只描述可见日常画面，不构造本人饲养、本人拍摄、同一个体、同一家庭或连续成长经历。公开农场、水族馆、动物园与户外来源未伪装成用户的家庭宠物生活。`checkedAt` 指本地来源证据与画面复核日期；此前保存的元数据不等于当日重访了所有 Commons 文件页。

## 视频与分包

8 个新视频均为 **8 秒、长边 480 像素、20fps、H.264 baseline、无音轨**，每段实际查看了间隔 0.5 秒的抽帧及封面。它们包括水族生物与仓鼠日常；因 CDN 下载不稳定及内容重复，未采用最初设想的 20 条视频配比，也未将未下载的远程链接算作内容。

`media-packages.json` 记录实际分配：media2 为 1,621,625 字节、media3 为 286,445 字节，各包视频均不足 1,800 KiB。8 张列表海报保留在主包，长边 320 像素、合计 44,416 字节；更清晰的复核原片与初始封面保存在 `content/`。

## 复核与验证

- `photo-review/mammal-groups.json`、`nonmammal-groups.json`、`nonmammal-extra-groups.json` 保存最终分组与配文。
- `photo-review/*pairs-*.jpg` 是实际查看的成组接触图；个别旧接触图含最终淘汰候选，采用范围与淘汰理由在 `nonmammal-final-review.json` 中明确记录。
- `photo-sources/selected.json` 保存 150 张新图的来源、许可、作者、元数据文件、下载副本及 SHA-256。
- `video-review/evidence.json` 记录逐视频抽帧复核；`feed-posters.jpg` 是最终小封面复核图。
- `review-evidence.json` 固定 **233 份复核文件**的 SHA-256，覆盖实际采用素材、来源元数据、文案与复核图。

内容专项 **56 项测试通过**。来源与运行数据审计无失败：完整分页能读到 360 条，圈子/话题/动物筛选与排除正确，所有新多图均有完整图片署名，原 260 条对象保持一致，媒体文件哈希、8 秒时长与分包大小相符。运行数据审计只使用隔离内存存储，不访问真实微信存储、账号、草稿或云端。最终目录 JS 为 444,002 字节。

以上是内容与本地媒体结构验收。微信手机视频播放、预览二维码与整体小程序编译由主任务单独验收，不以内容测试代替真机结果。

## 离线重建

```sh
python3 scripts/prepare-content-expansion.py --publish
npm run content:validate
npm run content:build
node scripts/prepare-curated-shapes.js
node --test tests/content-expansion.test.js tests/content-import.test.js tests/content-extension.test.js tests/content-serialization.test.js tests/content-catalog.test.js
node scripts/audit-content-runtime.js
```

默认不带 `--publish` 时只生成提案。正常发布要求恰好 100 条新增内容、复核证据哈希不变、当前目录仍完整保留原 260 条；如有其它新增条目或原条目被修改，脚本拒绝覆盖。采集期间使用的 `--allow-partial` 是显式增量选项，不代表已经完成用户的 100 条目标。
