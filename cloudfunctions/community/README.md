# 有宠有邻微信云开发后端

这是一份可部署的多人后端源码，不是已开通的在线服务。当前项目默认使用本机演示数据；前端已配置真实 AppID，云函数尚未部署，微信接口权限及真实微信双账号流程尚未验证。

云端实现 `docs/03-开发接口约定.md` 的全部云端 actions，不包含仅用于本机演示的 `demoVerifyIdentity`。用户、圈子关系、帖子评论、活动报名、站内消息和举报存入云数据库。身份只来自 `cloud.getWXContext().OPENID`。客户端提交的 `openid`、`isAdmin` 等字段会被拒绝，管理权限只来自云函数环境变量。

本次内容社区版本增加标题、分享类型、固定话题、封面选择、活动关联、关注流、字面搜索、点赞、私人收藏和可选公开个人资料。产品名称与包名改为「有宠有邻」/`youchong`，数据库集合继续使用 `yb_` 前缀，避免破坏既有数据。

v0.3 增加微信手机号核验、协议/隐私版本同意、独立的头像宠物展示开关和管理员宠物统计。真实核验尚未在 AppID、微信接口权限及真机上验证；默认不开启。界面仅能表述“手机号已核验”，该状态不代表法律实名审核或已完成合规审查。

v0.4 补齐服务端运营政策配置、账号频次限制、受保护维护入口、异步图片审核与加密回调，以及管理员运行状态页。部署工具和可检查的发布包见 [基础设施说明](../../infra/README.md)。这些代码不表示真实调度或微信能力已经配置。

## 1. 准备与部署

1. 申请微信小程序账号，取得自己的 AppID，在微信开发者工具中导入项目。先维持客户端 `config.js` 的 `mode: 'demo'`，确认页面工作正常。
2. 开通微信云开发环境；需要自行确认主体资质、服务类目、云资源费用、用户隐私保护指引和实际收集的信息。此代码不代表已经获得微信审核通过。
3. 在云数据库中创建下文列出的全部集合。**逐个配置客户端读、写均拒绝的规则，再写入任何真实数据。** 云函数使用服务端权限访问这些集合。不要使用“所有用户可读”的默认规则。
4. 配置索引。将 `cloudfunctions/community` 上传并部署为 `community`，选择云端安装依赖。目录不依赖小程序前端文件，唯一第三方依赖是 `wx-server-sdk`。运行环境使用微信支持的 Node.js 18 或更高版本；建议云函数超时 60 秒、内存至少 256 MB。函数最长执行时间必须短于图片处理的 120 秒租约，维护及注销任务最长执行时间也必须短于各自 5 分钟租约。
5. 云函数环境变量：

   | 变量 | 用途 |
   | --- | --- |
   | `DATABASE_RULES_CONFIRMED=true` | 完成所有集合 deny 规则及实际拒绝检查后设置。未设置时接口返回 `SETUP_REQUIRED`，不会存储个人数据。此变量是部署门槛，不会代替安全规则本身。 |
   | `ADMIN_OPENIDS` | 运营者 OpenID 逗号分隔白名单。留空则没有管理员。只配置在云函数环境变量中。 |
   | `TENCENT_MAP_KEY` | 仅服务端使用的腾讯位置服务 WebService Key，用于公开地点地址解析。已有坐标导航不依赖此项；缺少时仅地址地点不能解析。配置和实际微信验收见[附近导航与原文跳转](../../docs/14-附近导航与原文跳转.md)。 |
   | `OPERATOR_CONFIG` | 服务端 JSON：真实运营主体 `name`、联系方式 `contact`、实际保存/删除及备份期限 `retention`、`termsVersion`、`privacyVersion` 和审阅后明确设置的 `policyApproved:true`。缺项或未确认时协议保持草稿，真实手机号注册返回 `POLICY_NOT_CONFIGURED`。可选 `rateLimits` 见下文。 |
   | `MAINTENANCE_SECRET` | 至少 32 字节、非空白的独立秘密，仅供服务端外部调度调用维护，不能放客户端或提交仓库。 |
   | `MEDIA_REVIEW_MODE` | 缺省 `disabled`，需显式选择经真实环境验证的 `sync` 或 `async`。 |
   | `MEDIA_CALLBACK_TOKEN` / `MEDIA_CALLBACK_ENCODING_AES_KEY` / `MEDIA_CALLBACK_APP_ID` | 异步审核需填写微信消息推送安全模式的 Token、43 位 EncodingAESKey 和绑定 AppID；HTTP 回调必须校验签名、解密并核对 AppID。 |
   | `MEDIA_QUARANTINE_LOCK_CONFIRMED` | 实际确认普通客户端不能修改/删除服务端隔离快照后设为 `true`，是异步上传开启的必要条件。 |
   | `UPLOADS_ENABLED` | 默认不设置，图片上传关闭。完成第 4 节核验后才设为 `true`。 |
   | `CLOUD_FILE_PREFIX` | 完整云文件前缀，形如 `cloud://环境ID.实际存储桶/`，结尾必须带 `/`。从本环境真实文件 ID 确认，不能只填写环境 ID。 |
   | `PHONE_VERIFICATION_ENABLED` | 默认不设置。主体具备微信手机号获取能力、权限声明与实际调用核验完成后才设为 `true`。 |
   | `PHONE_HASH_SECRET` | 服务端稳定保存的高熵随机密钥，至少 32 字节且非空白，无默认值。只放云端环境/秘密管理中，不能放客户端、仓库或日志。见第 4 节的保管与轮换要求。 |

6. 将客户端 `config.js` 的 `mode` 改为 `cloud`，填写 `cloudEnv`。云环境 ID 是公开配置，管理员白名单和其他凭据不能放入客户端。
7. 管理员需通过真实微信身份访问一次小程序，并在云开发控制台的用户管理或受控的服务端身份查询中确认自己的 OpenID，再加入 `ADMIN_OPENIDS`。不要让客户端提交身份，也不要把调试身份输出留在公共接口或用户日志里。变更环境变量后重部署/重启以使其生效。
8. 使用管理员登录的小程序，在开发者工具调试控制台调用下例，设置真实试运营区域。普通用户调用会被拒绝；云控制台中没有微信用户上下文的裸调用也会被拒绝。

```js
wx.cloud.callFunction({
  name: 'community',
  data: {
    action: 'initialize',
    payload: {
      city: '你的城市',
      areas: ['你实际运营的片区'],
      contact: '真实可联系的运营者联系方式'
    }
  }
})
```

`initialize` 创建三个真实、空的圈子，并保存区域配置；不会生成示例帖子、活动、报名或虚构用户。重复初始化保留已有圈子和成员数，只更新区域设置。初始化不自动加入圈子。

## 2. 数据库集合与规则

创建以下 20 个集合，全部使用 [database.rules.json](./database.rules.json) 中的规则：

```json
{ "read": false, "write": false }
```

| 集合 | 内容 |
| --- | --- |
| `yb_users` | 个人资料与账号清理状态，不存储原始 OpenID |
| `yb_settings` | 城市、开放片区、联系信息；`maintenance` 文档保存维护游标、租约和摘要 |
| `yb_circles` | 圈子与成员计数 |
| `yb_memberships` | 圈子成员关系 |
| `yb_posts` | 帖子与评论数 |
| `yb_comments` | 帖子/活动评论 |
| `yb_events` | 活动及最多 100 人的报名 ID 列表 |
| `yb_registrations` | 按用户查活动的关系记录 |
| `yb_messages` | 私有站内通知 |
| `yb_blocks` | 单向存储、双向生效的屏蔽关系 |
| `yb_reports` | 举报记录及处理结论，运营者可在小程序中处理 |
| `yb_uploads` | 上传票据、归属与完成状态 |
| `yb_outbox` | 已提交活动变更的待发送通知 |
| `yb_likes` | 用户与帖子的点赞关系，唯一文档 ID 保证幂等 |
| `yb_bookmarks` | 本人私有的帖子收藏关系 |
| `yb_follows` | 用户关注关系，唯一文档 ID 保证幂等 |
| `yb_identities` | 私有手机号核验记录：用户 ID、HMAC 手机号摘要、脱敏号码、核验方式/时间、同意版本/时间；不保存原始号码 |
| `yb_phone_claims` | 以 HMAC 手机号摘要作为文档 ID 的占用关系，防止同号绑定多个活动账号 |
| `yb_rate_limits` | 账号、动作、时间窗的服务端频次计数及过期时间 |
| `yb_media_reviews` | 微信审核 trace 与票据/隔离快照的绑定、可信回执及清理信息 |

文件中的规则不会自动套用到云环境，必须部署者在控制台逐集合设置。函数故意不自动创建集合，以免在平台默认权限下写入私有信息。云开发环境的调用权限也应仅向本小程序开放。

帖子作者、关注列表和举报者默认只投影 `id/nickname/avatar`；当用户明确开启 `showPet=true` 且填写宠物时才附加 `pet:{name,type}`。个人主页的介绍只对本人或 `publicProfile=true` 开放；宠物资料对本人、`publicProfile=true` 或 `showPet=true` 开放。否则介绍/宠物分别为空字符串与 `null`。片区 `area` 永不进入公开主页；管理权限与手机号核验状态/脱敏号码只从本人的 profile/bootstrap/verifyPhone 返回。公开作者卡片、他人主页、关注列表、举报投影和统计不会包含任何手机号身份字段。所有业务 API 均不返回原始手机号、原始 OpenID、消息接收者标识、管理员名单、审核票据内部状态或数据库异常栈。

从 v0.1 升级到 v0.2 内容社区版本时，先创建 `yb_likes/yb_bookmarks/yb_follows` 三个新增集合及其拒绝读写规则和索引，再部署新版云函数及客户端。旧用户缺少 `publicProfile` 时一律视为 `false`，不会自动公开已填写的个人介绍或宠物资料；编辑资料未提交该选项时保留原选择。旧帖子缺少新字段时默认空标题、`daily` 类型、空话题、首图封面、无关联活动和 0 点赞，无需批量改写用户记录。

从 v0.2 升级到 v0.3 时，另需先创建 `yb_identities/yb_phone_claims` 两个私有集合。旧用户没有服务端身份记录/有效手机号占用关系时保持 `unverified`；不信任或迁移客户端保存的 `phoneVerified` 等标志。`showPet` 缺省始终为 `false`，**不会把已有 `publicProfile` 主页公开同意扩展为头像旁展示宠物**。资料接口支持局部更新：省略字段保留旧值，明确传空介绍/片区或 `pet:null` 才清空相应资料。

从 v0.3 升级到 v0.4，先创建 `yb_rate_limits/yb_media_reviews` 及拒绝读写规则，再补齐维护索引和部署新版。旧账号首次访问时服务端事务分配随机 `lifecycleId`，每次注销后重建生成新值；其不进入公开投影。核验、资料审核和上传等外部等待后的写入会检查账号代次，旧请求无法写入重建账号。

云函数每次冷启动会先确认全部集合可由服务端读取，缺少集合则返回 `SETUP_REQUIRED`，不会通过写入隐式创建默认权限的集合。该检查只验证集合存在，客户端拒绝规则仍需部署者实际验证。

## 3. 查询索引

除平台默认 `_id` 索引外，为实际使用的查询建立以下组合索引。`↑` 表示升序，`↓` 表示降序。字段顺序应和实际查询匹配；控制台若对某个组合查询返回缺失索引提示，按提示创建并验证，不要通过开放数据库权限解决。

| 集合 | 索引字段 |
| --- | --- |
| `yb_circles` | `active ↑, sort ↑` |
| `yb_users` | `status ↑, _id ↑`，供管理员按活动账号聚合宠物统计 |
| `yb_memberships` | `userId ↑, _id ↑` |
| `yb_posts` | `deleted ↑, _id ↓`；`deleted ↑, circleId ↑, _id ↓`；`deleted ↑, authorId ↑, _id ↓`；`deleted ↑, circleId ↑, authorId ↑, _id ↓`；`authorId ↑, _id ↑`；`authorId ↑, deleted ↑, _id ↑` |
| `yb_comments` | `targetType ↑, targetId ↑, deleted ↑, _id ↓`；`targetType ↑, targetId ↑, _id ↑`；`authorId ↑, _id ↑`；`replyToAuthorId ↑, _id ↑` |
| `yb_events` | `petPolicy ↑, _id ↓`；`hostId ↑, _id ↑` |
| `yb_registrations` | `userId ↑, _id ↑` |
| `yb_messages` | `toId ↑, _id ↓`；`toId ↑, isRead ↑, _id ↑`；`toId ↑, _id ↑`；`actorId ↑, _id ↑` |
| `yb_blocks` | `fromId ↑, _id ↑`；`toId ↑, _id ↑` |
| `yb_uploads` | `ownerId ↑, fileId ↑, status ↑`；`ownerId ↑, _id ↑`；`status ↑, _id ↑` |
| `yb_rate_limits` | `expiresAt ↑`；`userId ↑, _id ↑` |
| `yb_reports` | `reporterId ↑, _id ↑`；`status ↑, _id ↓` |
| `yb_outbox` | `actorId ↑, _id ↑` |
| `yb_likes` | `userId ↑, _id ↑`；`postId ↑, _id ↑`；`userId ↑, authorId ↑, _id ↑` |
| `yb_bookmarks` | `userId ↑, _id ↑`；`postId ↑, _id ↑`；`userId ↑, authorId ↑, _id ↑` |
| `yb_follows` | `fromId ↑, _id ↑`；`fromId ↑, _id ↓`；`toId ↑, _id ↑` |

`yb_identities` 按用户 ID 直接读取，`yb_phone_claims` 按 HMAC 摘要直接读取，均只需默认 `_id` 唯一索引。`yb_media_reviews` 的有界维护扫描使用默认 `_id` 顺序索引。维护另需 `yb_posts` 的 `deleted ↑, images ↑` 索引，以保护仍被真实帖子引用的图片。不得为了调试在任何私有集合开启客户端读取。

帖子、评论、活动、消息与屏蔽列表支持 `limit`（默认 20，最大 50）及 `cursor`；返回 `nextCursor` 表示还有下一页。详情的评论也返回可选 `nextCursor`。圈子目前最多 50 个。计数汇总与注销过程会分页遍历本人记录，适合初期社区；大量历史数据时应移为独立统计及后台清理任务。

`listPosts` 的 `feed` 为 `discover`（默认）、`following`（本人关注的作者）或 `circles`（本人加入的圈子）；可叠加 `topic/query/authorId/bookmarked/circleId/mine`，全部取交集。搜索词最多 60 字，对标题、正文和话题进行不区分字母大小写的**字面包含**匹配，不执行正则表达式，也不连接外部搜索引擎。每次请求扫描最多 5 批、每批最多 50 条原始帖子，按消费到的最后一个原始记录返回游标。稀疏搜索可能出现本页无结果但仍有 `nextCursor`，客户端应继续分页，不能把空页直接当作搜索结束。改变筛选条件后应清空游标。关注/加入/收藏集合先按本人分页读取，再进行帖子过滤；这是首批用户规模的实现，大规模内容检索需要服务端索引、专门搜索或物化信息流。

`listFollowing` 同样分页，只返回本人的关注对象公共资料；`getUserProfile` 的帖子使用同样的游标机制。收藏没有面向他人的列表接口；任何用户都只能查询自己的收藏状态和收藏内容。

## 4. 手机号核验与内容安全

### 微信手机号核验与发布/互动权限

`getPolicies` 返回服务端版本、运营信息、协议/隐私条款和 `isDraft`。`bootstrap.registration` 返回当前 `termsVersion/privacyVersion`（缺省 `2026-09-29`）、`policyConfigured` 及 `phoneEnabled`。页面与核验提交使用服务端当前版本，客户端配置不能替代运营政策确认。只有手机号开关已开启、非空白密钥至少 32 字节、服务端 SDK 存在 `phonenumber.getPhoneNumber` 能力时，`phoneEnabled` 才为 `true`；这表示本地部署配置完整，不等于微信已批准账号能力。

运营字段必须符合本次真实收集、使用、保存和删除做法；`policyApproved:true` 是运营者确认，不是平台或法律认证。缺少有效运营政策时真实注册返回 `POLICY_NOT_CONFIGURED`。

客户端使用微信手机号授权回调的一次性 `code`，调用：

```js
{
  action: 'verifyPhone',
  payload: {
    code: '微信返回的一次性凭证',
    consent: {
      accepted: true,
      termsVersion: '2026-09-29',
      privacyVersion: '2026-09-29'
    }
  }
}
```

未明确同意或版本不匹配返回 `CONSENT_REQUIRED`；不能传入手填号码、客户端“已核验”标志或其他证明。云函数只由服务端调用 `cloud.openapi.phonenumber.getPhoneNumber`，校验返回结构后在该次调用的内存中规范化国家码/号码，以 HMAC-SHA256 得到稳定摘要；应用不把原始号码写入数据库、响应或日志。`config.json` 声明了 `phonenumber.getPhoneNumber`，仍需确认主体资格、接口计费/额度和实际返回字段。

在同一个数据库事务中创建用户身份和手机号占用记录。身份保存 `method:'wechat_phone'`、状态、脱敏号码、HMAC 摘要以及核验/同意版本与时间。另一正常账号或正在注销的账号占用该手机号时拒绝绑定。并发请求只保留第一份成功绑定；同一账号已核验后重试返回既有结果，不重新兑换已经消耗的 `code`，也不切换到另一个手机号。本版没有换绑入口。失败的微信核验或数据库事务不生成已核验状态。

**HMAC 密钥必须稳定保管，不能随意更换或在每次启动时随机生成。** 更换密钥会使同一手机号产生另一个摘要，使已有重复绑定检测失效。需要轮换时必须先设计含旧密钥兼容、重新核验/迁移的方案；本版不提供自动轮换或恢复原号码的能力。妥善限制密钥及云数据库访问权限，备份时也遵循这一约束。

未核验账号仍可浏览、修改资料、举报、屏蔽、处理自己的删除/退出操作及注销。新增帖子/评论、创建或修改活动、加入圈子/报名、关注/点赞/收藏、申请及完成图片上传均要求服务端状态为 `phone_verified`，否则返回友好 `VERIFICATION_REQUIRED`。加入/报名/关注/点赞/收藏的 `false` 撤销操作不要求核验；管理员取消活动也不要求核验，但仍检查管理员身份。管理员发布与其他账号使用相同核验门槛，没有硬编码绕过。门禁在入口和写事务中均验证身份记录与手机号占用关系，客户端标志不起作用。

注销先将账号设为正在清理，然后事务删除身份及本人占用的手机号摘要；中断可重试。正在清理的账号不能通过延迟返回的核验结果复活。清理完成后重新进入时为未核验账号；手机号可由再次完成微信核验的账号绑定。实际邀请用户前，应完成小程序主体资料、清晰的运营者联系方式以及用户协议/隐私政策内容审查，不能把代码内的同意按钮或状态标签当作合规完成证明。

### 文字

生产入口对帖子（包括新增标题与话题）、评论、个人资料、活动及取消原因调用微信 `security.msgSecCheck` v2。只有 `suggest === 'pass'` 才写入；接口不可用、账号没有权限或没有明确通过结果均拒绝发布。`config.json` 声明了所需 OpenAPI 权限，但权限声明不等于微信已经批准能力。上线前用真实账号检查调用资格、微信侧隐私配置、调用限制和审核返回结构。

帖子标题最多 40 字；类型仅 `daily/question/meetup`；最多选择 3 个固定话题：宠物治愈时刻、新手养宠、一起散步、没养宠也能来、宠物友好去处、养宠经验。标题不代替正文：仍需正文或至少一张图片。封面必须指向本次已审核图片数组的有效索引，无图时仅允许 0。活动关联必须在提交时存在且对作者可见；读取时再次按当前访问者的屏蔽关系检查，无效/不可见活动返回 `event:null`，不会通过帖子暴露被屏蔽组织者的活动信息。

### 图片：显式审核模式与可信回执

上传默认关闭，需同时设置 `UPLOADS_ENABLED=true`、真实 `CLOUD_FILE_PREFIX` 和经验证的 `MEDIA_REVIEW_MODE`。异步模式还要求完整回调配置、`MEDIA_QUARANTINE_LOCK_CONFIRMED=true` 和服务端 `mediaCheckAsync/getTempFileURL` 能力。配置满足不等于平台接口、回调或存储权限已经实测。

1. 客户端申请随机票据，再上传至 `community/incoming/用户公开ID/随机ID.ext`。票据 15 分钟过期，服务端校验所有者和完整 fileId，不接受别人的票据或其他环境同名文件。
2. `sync`：下载并检查 JPEG/PNG/WebP 文件头及 5 MB 应用上限，调用 `security.imgSecCheck`。只有明确成功才把同一份字节写入随机 `community/published/` 路径；账号支持的大小、尺寸和接口限额需真机确认。
3. `async`：先将隔离路径登记到票据，再把同一份字节写入客户端不可修改的 `community/quarantine/` 快照，保存 SHA-256，提交 `security.mediaCheckAsync` v2 并绑定 trace。`completeUpload` 返回 `{status:'pending',ticketId}`，此时不能发帖。
4. 微信消息推送须设置为安全模式，并把真实 HTTP 入口接到 `community`。回调处理 GET 校验及 POST 通知，核对签名、AES 密文、内外 AppID、事件及 trace；不接受明文结果或客户端伪造事件。提前到达的可信回执可先保存、再与返回的 trace 绑定；持久化失败返回 HTTP 503 以便重试。端到端回调送达需在真实账号验证。
5. 客户端调用 `getUploadStatus({ticketId})` 查询本人票据。只有可信回执为 pass，且 30 分钟审核期限、账号代次和事务租约有效，才重读隔离快照核对 SHA-256 并发布。拒绝、过期或字节改变不会生成可发帖的 fileId；并发轮询只允许一份成功发布。审核结果不能由客户端传入。
6. 同步和异步发布都先在票据登记预期 public 路径，再写服务器副本，避免写入后中断丢失清理线索。发帖事务只接收本人 `complete` 票据，一份图片仅用于一篇帖子。临时/隔离文件删除失败及放弃发布的文件由维护重试；注销清理失败则维持可重试状态。
7. 必须用普通账号 A/B 验证：不能覆盖或删除服务端 `published` 和 `quarantine` 文件，只允许写各自的临时文件。若平台规则使服务器副本仍归调用者可写，应改为服务端独占存储区域或经验证的路径规则后才开启图片。随机路径不等于私密相册，本版只上传准备公开的宠物照片；已公开图片的外部缓存/截图不能通过删源文件撤回。

客户端收到 `pending/rejected/expired` 应保留草稿并显示真实状态，只有 `complete.fileId` 可提交帖子。接口不兼容时保持图片关闭，不能跳过内容检查。

### 频次控制

云端按可信账号、动作与固定时间窗执行事务计数，超过上限返回 `RATE_LIMITED`。默认每分钟：帖子/创建活动/举报 10 次，评论/资料/完成上传 30 次，修改活动/申请上传 20 次，加入/报名/关注 60 次，点赞/收藏 120 次，实际新手机号兑换 5 次。撤销加入/报名/关注/点赞/收藏不占用次数；已核验账号幂等重试不重新兑换凭证。

`OPERATOR_CONFIG.rateLimits` 可按已支持动作覆盖，例如 `{"createPost":{"limit":5,"windowMs":60000}}`。配置必须为有效整数，上限 1–10000，窗口 1000–86400000 毫秒，否则使用默认值。计数保留至窗口结束后 24 小时，再由维护清理；注销也清除本人的计数。它不替代平台配额和云资源预算限制。

### 后台维护与运行状态

`service.runMaintenance` 仅由受保护的 `__maintenance` 入口调用。外部调度器使用服务端 SDK、云调用凭据及独立 `MAINTENANCE_SECRET`，请求形状为：

```js
{ action: '__maintenance', maintenanceSecret: process.env.MAINTENANCE_SECRET, payload: { limit: 20 } }
```

服务端对秘密作常数时间比较，拒绝任何带可信微信 `OPENID` 的客户端调用。`Type:'Timer'`、`TriggerName` 或类似客户端字段没有授权作用。本仓库不把伪造事件字段当作原生定时器身份；需在运行环境配置真正的外部调度，执行 [维护工具](../../infra/README.md) 中的服务端命令。小程序没有手工执行维护入口。

每次持有 5 分钟单例租约，处理最多 3 个通知任务，并分别有界扫描上传、审核记录和过期计数（`limit` 默认 20，允许 1–50）。上传清理优先重试 `cleanup`，然后按持久游标扫描：过期临时上传、审核拒绝/过期、24 小时未发布的完成上传、已删帖残留、公开成功后的源文件，以及孤立/过期审核记录。清理前事务锁定票据并再次检查状态；仍被真实帖子引用的公开图片会保留，即使旧票据缺少 `postId`。清理失败保留重试线索，不标记为已完成。

管理员 `getHealth` 只返回能力配置、队列计数及维护最近运行/成功时间与错误类别，不返回秘密或用户名单。`maintenanceEnabled` **仅表示维护秘密已配置**，不表示调度器已启动或执行成功；以 `maintenance.lastRunAt/lastSuccessAt` 和真实调度记录确认运行。各队列最多采样 100 条，`countsLimited:true` 表示至少一个计数受限，不能当作精确总数。

## 5. 事务、屏蔽、通知与注销

- 圈子成员关系和成员计数在同一事务更新；重复加入/退出不会重复增减。
- 点赞、收藏和关注使用确定的关系 ID，在事务内检查用户、内容及屏蔽状态；点赞数、关注/粉丝数与关系同时变更，重复点击或并发重试不会重复累计。不能关注自己。点赞、关注与收藏不发送额外站内通知。
- 管理员 `getPetStats` 分页汇总活动账号，返回总账号数、有/未填写宠物的资料数、按 `cat/dog/other` 分类数，以及开启 `showPet` 且已填写宠物的头像公开资料数。只有 `publicProfile` 开启不会计入头像公开数。结果不含用户名单、名字、手机号或位置，且明确标注“每个账号最多登记一只宠物；未填写不代表没有宠物”。大规模账号下应将聚合改为受控的增量统计任务。
- 活动报名在同一事务中读取活动与用户、检查开始时间/状态/名额、写报名关系并更新报名 ID 列表。并发超额请求失败，重复报名幂等。开始后/取消后仍允许已报名者退出。修改容量不能少于现有报名人数。
- 云数据库事务内只按确定的文档 ID 读取，不依赖事务不支持的集合查询。活动容量上限为 100；报名者清单不会作为公共响应返回。
- 活动修改/取消与通知任务在同一事务提交。通知通过 outbox 逐用户事务投递，消息 ID 确定且重试不会重复。每次成功调用最多处理 3 个任务，失败任务由后续请求或受保护维护重试。配置外部调度后可在无人访问时处理队列；这仍属于站内通知，不是微信订阅消息。失败排查可查看 `yb_outbox` 和管理员运行状态。
- 评论通知只发给内容作者与被回复者，用户只能读/标记自己的消息。活动结束或取消后仍可评论，方便后续沟通。
- 屏蔽双向生效：双方帖子、评论、活动组织者内容在列表和详情中隐藏，直接传 ID 也无法绕过。已有来自被屏蔽者的通知隐藏。屏蔽组织者会退出其活动并释放名额，反向屏蔽亦然；同场的普通参与者之间屏蔽不强制退出第三方活动。
- 屏蔽也会解除双方关注，移除双方对彼此帖子的点赞与收藏并更新计数；公开主页、关注和点赞/收藏操作都会检查双向屏蔽。解除屏蔽不会恢复这些关系。删帖清理该帖的所有点赞与收藏；注销清理本人及指向本人的关注、本人点赞/收藏及本人帖子收到的关系，重新进入时从空资料和空关系开始。
- 注销先标记账号正在清理并取得服务端删除租约；并发注销请求被拒绝，失败退出释放租约以供重试，进程中断后待租约过期重试。并发创建内容、报名、上传及通知接收均重新校验用户状态。随后清除公开内容、站内通知、个人资料、屏蔽与上传，解除圈子和活动关系。组织者的活动保留取消记录并显示“已注销用户”。最小化保留不含原始资料的删除状态和内容墓碑。清理中断可再次调用 `deleteAccount`；重新 `bootstrap` 只在清理结束后创建新代次的空资料账号。
- 举报只接受有效目标，并写入私有集合。小程序中的管理员举报页调用 `listReports` 查看待处理/全部举报，默认每页 20 条并支持游标分页；普通用户无法访问。返回举报原因、补充说明、目标摘要、举报者公共昵称头像，不包含任何 OpenID、他人个人介绍/片区/宠物资料或内部处理者身份。评论举报保存原帖/活动的链接，评论后续删除仍可定位。管理摘要只用于有权限的治理工作。
- 管理员调用 `resolveReport({id,status:'resolved'|'dismissed',note?})` 处理举报，说明选填、最多 300 字并通过内容检查。处理结论、处理者与时间以及给举报人的私有系统消息在同一事务提交；并发处理或重试保持首个结论，既不覆盖也不重复通知。只改变举报状态，不自动删除内容；管理员可在查看后另用 `deletePost/deleteComment` 移除内容。老版本 `pending` 状态兼容为待处理 `open`。

若注销时还有持有效租约的图片外部写入，账号先进入 `deleting` 并返回可重试的 `ACCOUNT_UNAVAILABLE`，保留唯一的票据与清理路径。已进入后台的上传不能再发布；待其结束或租约过期后，从现有清理提示重试注销。不能在外部上传尚可晚到时删除票据并宣称注销成功。真实存储适配器的回归已覆盖“隔离写入暂停 → 注销 → 晚到写入 → 审核/删除均失败 → 维护及注销重试”。

v0.4 已实现上述频次控制。用户封禁、完整人工预审台和企业级审计保留策略仍需按运营规模补齐。
